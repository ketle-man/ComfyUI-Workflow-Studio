# 第10章 AI TOOL － ローカルAIを助手にする

Workflow Studioは、パソコンの中で動く **ローカルAI（大規模言語モデル）** と連携できます。
ローカルAIを用意すると、次のようなことができるようになります。

- 日本語で考えた内容を、英語のプロンプトに翻訳する
- AIとチャットしながら、プロンプトのアイデアを出してもらう
- 画像を見せて、その画像の説明やプロンプト、タグを作ってもらう
- ワイルドカード用の候補リストを作ってもらう

インターネット上のサービスではなく、自分のパソコンの中で動くので、
**入力した内容や画像が外部に送られない** のが大きな特長です。

> **ポイント**
> AI機能は「あると便利」な機能です。使わなくても、Workflow Studioの基本機能はすべて使えます。
> パソコンの性能（特にGPUのメモリ）に余裕がある方は、ぜひ試してみてください。

---

## 10-1 ローカルAIソフトを準備する

### 対応しているソフト
Workflow Studioは、次の4つのローカルAIソフトに対応しています。

| ソフト | 特徴 | 標準のアドレス |
| --- | --- | --- |
| **Ollama**（オラマ） | 定番。モデルのダウンロードから実行までかんたん | `http://localhost:11434` |
| **LM Studio** | 画面で操作できる。モデル探しもアプリ内でできる | `http://localhost:1234` |
| Lemonade Server | AMD製のGPU・NPUでも動かしやすい | `http://localhost:13305` |
| Unsloth | APIキーなどの追加設定が必要（上級者向け） | `http://localhost:8888` |

はじめての方には **Ollama** をおすすめします。本章では、Ollamaを例に説明します。

> **ポイント**
> アドレスの `localhost` は「自分のパソコン」、その後ろの数字は **ポート番号** です（第2章 2-4）。
> ComfyUIと同じように、AIソフトもそれぞれ決まったポート番号で待ち受けています。

### Ollamaの準備
1. Ollamaの公式サイトから、お使いのOS用のインストーラーをダウンロードして、インストールします。
2. Ollamaを起動します（Windowsでは、インストール後に自動で起動し、タスクバーの通知領域に常駐します）。
3. 使うAIモデルをダウンロードします。コマンドプロンプトなどで、次のように入力します。

   ```
   ollama pull （モデル名）
   ```

   モデル名は、Ollamaの公式サイトのモデル一覧で確認できます。

> **モデル選びの目安**
> - **画像を読み取る機能（VLM）も使いたい** → 画像入力（vision）に対応したモデルを選ぶ
>   （作者の検証では、Gemma 4 の `e4b` などで画像生成・画像読み取りがうまく動いています）
> - **GPUのメモリが少ない** → パラメータ数の小さいモデル（数B＝数十億程度）を選ぶ
> - 翻訳の精度を重視するなら、日本語が得意なモデルを選ぶ
>
> AIモデルの世界は変化が速いので、新しいモデルも試してみてください。

> **注意：GPUのメモリの取り合い**
> ローカルAIも、画像生成と同じく **GPUのメモリ（VRAM）** を使います。
> 両方を同時に動かすと、メモリが足りなくなって画像生成が遅くなったり、エラーになったりします。
> 対策は 10-3 で説明します。

## 10-2 AI TOOLタブを使う

Workflow Studio本体の **AI TOOL** タブを開きます。
画面は4つの部分に分かれていて、すべて同時に表示されます。

| 部分 | できること |
| --- | --- |
| 翻訳 | 日本語・英語・中国語などの翻訳 |
| Chat | AIとの会話。条件がそろえば、会話から画像生成も |
| TOOLS | 画像の読み取り（VLM）、ワイルドカード作成 |
| 設定 | 使うAIソフト・モデルの設定 |

### 最初に：設定でAIソフトとつなぐ
1. **設定** の **バックエンド** で、使うソフト（例：Ollama）を選びます。
2. **接続設定** のアドレスを確認します。Ollamaを標準のまま使っている場合は、変更不要です。
3. **接続テスト** を押します。「接続成功」と表示されればOKです。
4. **モデル選択** の **更新** を押し、一覧から使うモデルを選びます。
5. **設定を保存** を押します。

> **ポイント**
> ここでの設定は、ComfyUI側のWS Libraryの **A（AI TOOL）** タブと共通です。
> 一方、プロンプトタブ（第7章）とTaggerタブには、それぞれ専用の **歯車ボタン** 設定があります。
> 「AI TOOLタブでは使えるのに、プロンプトタブでは Disconnected」というときは、プロンプトタブの歯車ボタンでも同じように設定してください。

> **うまくつながらないとき**
> - Ollamaなどのソフトが起動しているか確認します。
> - LM Studioは、アプリ内で **サーバーを起動** しておく必要があります。
> - アドレスのポート番号が、ソフト側の設定と合っているか確認します。
> - モデルの一覧が空のときは、モデルがダウンロードされているか確認します。

### 翻訳
1. 翻訳元と翻訳先の言語を選びます（**⇄（入れ替え）** ボタンで入れ替え）。
2. 入力欄に文章を書き、**翻訳** を押します。
3. 結果を **コピー** して、生成UIやプリセットに貼り付けます。

> **ポイント**
> 小さなモデルは、翻訳せずに元の文章をそのまま返してしまうことがあります。
> その場合は「モデルが原文をそのまま返しました」と表示されるので、別のモデルを試してください。

### Chat
入力欄に話しかけて、**Enter** で送信します（**Shift＋Enter** で改行）。
会話の流れを覚えているので、「もっと明るい雰囲気にして」のような続けての依頼もできます。
**Clear** で会話をリセットします。

> **ポイント：チャットから画像を生成する（上級）**
> 「ツール呼び出し（Tool Calling）」に対応したモデルを使うと、
> チャットで「猫の絵を描いて」と頼むだけで、生成UIに読み込んだワークフローで画像が生成され、チャット内に表示されます。
> この機能は、入力欄の横の **画像生成を許可する** のチェックでオン・オフできます。

### TOOLS － 画像を読み取る（VLM）
画像入力に対応したモデル（VLM）を使うと、画像の内容をAIに読み取らせることができます。

1. **TOOLS** の枠に、画像（PNG／JPG／WebP）をドロップします。
2. 作業を選びます。

   | 作業 | 内容 |
   | --- | --- |
   | 画像の解説 | 画像に何が写っているかを文章で説明する |
   | プロンプト作成 | 画像を再現するためのプロンプトを作る |
   | Create tags（英語表示のまま） | 画像の要素をタグ形式で書き出す |
   | Create wildcards（英語表示のまま） | カテゴリー名と件数を指定して、ワイルドカードの候補を作る（画像は不要） |

3. **実行** を押します。結果はコピーして使えます。

> **例**
> 気に入ったイラストの雰囲気をまねしたいとき、その画像から「プロンプト作成」をして、
> できたプロンプトを生成UIで使ってみる － という使い方ができます。

### ComfyUIの画面の中でも使える
同じAI機能は、ComfyUI側のWS Libraryの **A** タブでも使えます。
ノード画面で作業しながら、ちょっと翻訳したいときに便利です。

## 10-3 VRAMの解放とメモリ管理

10-1で触れたとおり、ローカルAIと画像生成は、GPUのメモリ（VRAM）を取り合います。
Ollamaは、一度使ったモデルをしばらくメモリに置いたままにするため、
AIを使ったあとに画像生成をすると、メモリが足りなくなることがあります。

### 手動で解放する
AI TOOLの設定にある **モデルをアンロード** を押すと、AIモデルがメモリから降ろされ、VRAMが空きます。
（Ollamaの場合は、読み込まれているすべてのモデルが降ろされます）

### 生成の前に自動で解放する
設定タブの **VRAM調整（Ollama）** で、画像生成の直前に自動でOllamaのモデルを降ろすように設定できます。

| 生成前の動作 | 動き |
| --- | --- |
| 何もしない | 自動では降ろさない |
| 空きが目標未満のときだけ必要な分をアンロード | 空きVRAMが **目標の空き（GB）** より少ないときだけ降ろす |
| 毎回すべてアンロード | 生成のたびに、必ずすべて降ろす |

> **ポイント**
> どれを選べばよいか迷ったら、「空きが目標未満のときだけ必要な分をアンロード」がおすすめです。
> 目標の空きには、画像生成に必要なメモリの量（使うモデルによって異なります）を目安に入力します。
> **今すぐすべてアンロード** ボタンで、その場ですぐに解放することもできます。

> **注意**
> この自動解放は、Ollamaだけが対象です。LM Studioなどを使っている場合は、手動で解放してください。

## 10-4 セキュリティ上の注意

### 標準では「自分のパソコン」のAIにだけつながる
安全のため、Workflow StudioがつなぐAIソフト（Ollama、LM Studioなど）は、標準では
**同じパソコンの中（localhost／127.0.0.1）で動いているもの** に限られています。

### 別のパソコンのAIを使いたいとき
家庭内LANにある別のパソコン（GPUの強いパソコンなど）でOllamaを動かして使いたい場合は、
環境変数 **`WFS_ALLOWED_BACKEND_HOSTS`** に、つなぎたいパソコンのアドレスを登録して、ComfyUIを再起動します。

```
WFS_ALLOWED_BACKEND_HOSTS=192.168.1.20:11434
```

複数ある場合は、カンマ（,）で区切って並べます。
環境変数の設定方法は、ComfyUIの起動方法によって異なります。

### ComfyUIを `--listen` 付きで起動している場合
ComfyUIを `--listen` オプション付きで起動すると、同じネットワークにいるほかのパソコンやスマホからも
ComfyUI（とWorkflow Studio）にアクセスできるようになります。
その場合、アクセスできる人なら誰でも、あなたのAIソフトや画像を使えてしまいます。

> **注意**
> `--listen` は、家庭内LANなど **信頼できるネットワークでだけ** 使ってください。
> カフェや公共のWi-Fiでは使わないようにしましょう。

> **この章のまとめ**
> - ローカルAI（Ollamaなど）を用意すると、翻訳・チャット・画像の読み取りができる。入力内容は外部に送られない
> - AI TOOLタブの設定で、バックエンド・アドレス・モデルを選び、接続テストをする
> - プロンプトタブとTaggerタブには、別に歯車ボタンの設定がある
> - AIと画像生成はVRAMを取り合う。「モデルをアンロード」や「VRAM調整（Ollama）」で解放する
> - 標準では自分のパソコンのAIにだけつながる。`--listen` は信頼できるネットワークだけで
