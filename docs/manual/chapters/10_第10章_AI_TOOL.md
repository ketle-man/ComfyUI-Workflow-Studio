# 第10章 AI TOOL － ローカルAIを助手にする

Workflow Studioは、パソコンの中で動く **ローカルAI（大規模言語モデル）** と連携できます。
ローカルAIを用意すると、次のようなことができるようになります。

- 日本語で考えた内容を、英語のプロンプトに翻訳する
- AIとチャットしながら、プロンプトのアイデアを出してもらう
- 画像を見せて、その画像の説明やプロンプト、タグを作ってもらう
- ワイルドカード用の候補リストを作ってもらう
- **スキル** を選んで、プロンプト作り・ストーリーボード・不具合の相談など、得意分野を切り替える（v0.9.5〜）
- 生成した画像が依頼どおりかをAIにチェックさせて、足りない点だけ直す（v0.9.5〜）
- 画像に写っている文字を読み取る（OCR、v0.9.5〜）

インターネット上のサービスではなく、自分のパソコンの中で動くので、
**入力した内容や画像が外部に送られない** のが大きな特長です。

> **ポイント**
> AI機能は「あると便利」な機能です。使わなくても、Workflow Studioの基本機能はすべて使えます。
> パソコンの性能（特にGPUのメモリ）に余裕がある方は、ぜひ試してみてください。

## 10-1 ローカルAIソフトを準備する

### 対応しているソフト
Workflow Studioは、次の4つのローカルAIソフトに対応しています。

| ソフト | 特徴 | 標準のアドレス |
| --- | --- | --- |
| **Ollama**（オラマ） | 定番。モデルのダウンロードから実行までかんたん | `http://localhost:11434` |
| **LM Studio** | 画面で操作できる。モデル探しもアプリ内でできる | `http://localhost:1234` |
| Lemonade Server | AMD製のGPU・NPUでも動かしやすい | `http://localhost:13305` |
| Unsloth | APIキーなどの追加設定が必要（上級者向け） | `http://localhost:8888` |

はじめての方には **Ollama** をおすすめします。本章では、Ollamaを例に説明します。

> **ポイント**
> アドレスの `localhost` は「自分のパソコン」、その後ろの数字は **ポート番号** です（第2章 2-4）。
> ComfyUIと同じように、AIソフトもそれぞれ決まったポート番号で待ち受けています。

### Ollamaの準備
1. Ollamaの公式サイトから、お使いのOS用のインストーラーをダウンロードして、インストールします。
2. Ollamaを起動します（Windowsでは、インストール後に自動で起動し、タスクバーの通知領域に常駐します）。
3. 使うAIモデルをダウンロードします。コマンドプロンプトなどで、次のように入力します。

   ```
   ollama pull （モデル名）
   ```

   モデル名は、Ollamaの公式サイトのモデル一覧で確認できます。

> **モデル選びの目安**
> - **画像を読み取る機能（VLM）も使いたい** → 画像入力（vision）に対応したモデルを選ぶ
>   （作者の検証では、Gemma 4 の `e4b` などで画像生成・画像読み取りがうまく動いています）
> - **GPUのメモリが少ない** → パラメータ数の小さいモデル（数B＝数十億程度）を選ぶ
> - 翻訳の精度を重視するなら、日本語が得意なモデルを選ぶ
>
> AIモデルの世界は変化が速いので、新しいモデルも試してみてください。

> **注意：GPUのメモリの取り合い**
> ローカルAIも、画像生成と同じく **GPUのメモリ（VRAM）** を使います。
> 両方を同時に動かすと、メモリが足りなくなって画像生成が遅くなったり、エラーになったりします。
> 対策は 10-3 で説明します。

## 10-2 AI TOOLタブを使う

Workflow Studio本体の **AI TOOL** タブを開きます。
画面は4つの部分に分かれていて、すべて同時に表示されます。

| 部分 | できること |
| --- | --- |
| 翻訳 | 日本語・英語・中国語などの翻訳 |
| Chat | AIとの会話。スキルで得意分野を切り替えられる。条件がそろえば、会話から画像生成も |
| TOOLS | 画像の読み取り（VLM）、文字起こし（OCR）、ワイルドカード作成 |
| 設定 | 使うAIソフト・モデルの設定 |

> **ポイント：翻訳と設定はたためる（v0.9.5〜）**
> 翻訳と設定の見出しの右端にある矢印（◀／▶）を押すと、その部分が細い帯にたたまれ、空いた幅をChatとTOOLSが使います。
> 帯のどこかをクリックすると元に戻ります。たたんだ状態は、次に開いたときも保たれます。

### 最初に：設定でAIソフトとつなぐ
1. **設定** の **バックエンド** で、使うソフト（例：Ollama）を選びます。
2. **接続設定** のアドレスを確認します。Ollamaを標準のまま使っている場合は、変更不要です。
3. **接続テスト** を押します。「接続成功」と表示されればOKです。
4. **モデル選択** の **更新** を押し、一覧から使うモデルを選びます。
5. **設定を保存** を押します。

> **ポイント**
> ここでの設定は、ComfyUI側のWS Libraryの **A（AI TOOL）** タブと共通です。
> 一方、プロンプトタブ（第7章）とTaggerタブには、それぞれ専用の **歯車ボタン** 設定があります。
> 「AI TOOLタブでは使えるのに、プロンプトタブでは Disconnected」というときは、プロンプトタブの歯車ボタンでも同じように設定してください。

> **うまくつながらないとき**
> - Ollamaなどのソフトが起動しているか確認します。
> - LM Studioは、アプリ内で **サーバーを起動** しておく必要があります。
> - アドレスのポート番号が、ソフト側の設定と合っているか確認します。
> - モデルの一覧が空のときは、モデルがダウンロードされているか確認します。

### 翻訳
1. 翻訳元と翻訳先の言語を選びます（**⇄（入れ替え）** ボタンで入れ替え）。
2. 入力欄に文章を書き、**翻訳** を押します。
3. 結果を **コピー** して、生成UIやプリセットに貼り付けます。

> **ポイント**
> TOOLSで読み取った文字（10-8のOCRなど）は、TOOLSの **翻訳へ送る** で、この入力欄にそのまま入れられます。

> **ポイント**
> 小さなモデルは、翻訳せずに元の文章をそのまま返してしまうことがあります。
> その場合は「モデルが原文をそのまま返しました」と表示されるので、別のモデルを試してください。

### Chat
入力欄に話しかけて、**Enter** で送信します（**Shift＋Enter** で改行）。
会話の流れを覚えているので、「もっと明るい雰囲気にして」のような続けての依頼もできます。
**Clear** で会話をリセットします。

> **ポイント：チャットから画像を生成する（上級）**
> 「ツール呼び出し（Tool Calling）」に対応したモデルを使うと、
> チャットで「猫の絵を描いて」と頼むだけで、生成UIに読み込んだワークフローで画像が生成され、チャット内に表示されます。
> この機能は、入力欄の横の **画像生成を許可する** のチェックでオン・オフできます。

> **ポイント**
> Chatの上にあるドロップダウンで **スキル** を選ぶと、AIの得意分野を切り替えられます（10-5）。
> AIの返事は、見出し・箇条書き・コードの枠を整えて表示されます（v0.9.5〜）。

### TOOLS － 画像を読み取る（VLM）
画像入力に対応したモデル（VLM）を使うと、画像の内容をAIに読み取らせることができます。

1. **TOOLS** の枠に、画像（PNG／JPG／WebP）をドロップします。
2. 作業を選びます。

   | 作業 | 内容 |
   | --- | --- |
   | 画像の解説 | 画像に何が写っているかを文章で説明する |
   | プロンプト作成 | 画像を再現するためのプロンプトを作る |
   | Create tags（英語表示のまま） | 画像の要素をタグ形式で書き出す |
   | Create wildcards（英語表示のまま） | カテゴリー名と件数を指定して、ワイルドカードの候補を作る（画像は不要） |
   | 文字起こし（OCR） | 画像に写っている文字を読み取る（10-8） |

3. **実行** を押します。
4. 結果の下のボタンで、結果を使います（v0.9.5〜）。

   | ボタン | 動き |
   | --- | --- |
   | 翻訳へ送る | 翻訳の入力欄に入れる（翻訳がたたまれていれば開く） |
   | Chatへ送る | Chatの入力欄に追加する |
   | コピー | クリップボードにコピーする |

> **例**
> 気に入ったイラストの雰囲気をまねしたいとき、その画像から「プロンプト作成」をして、
> できたプロンプトを生成UIで使ってみる － という使い方ができます。

### ComfyUIの画面の中でも使える
同じAI機能は、ComfyUI側のWS Libraryの **A** タブでも使えます。
ノード画面で作業しながら、ちょっと翻訳したいときに便利です。

## 10-3 VRAMの解放とメモリ管理

10-1で触れたとおり、ローカルAIと画像生成は、GPUのメモリ（VRAM）を取り合います。
Ollamaは、一度使ったモデルをしばらくメモリに置いたままにするため、
AIを使ったあとに画像生成をすると、メモリが足りなくなることがあります。

### 手動で解放する
AI TOOLの設定にある **モデルをアンロード** を押すと、AIモデルがメモリから降ろされ、VRAMが空きます。
（Ollamaの場合は、読み込まれているすべてのモデルが降ろされます）

### 生成の前に自動で解放する
設定タブの **VRAM調整（Ollama）** で、画像生成の直前に自動でOllamaのモデルを降ろすように設定できます。

| 生成前の動作 | 動き |
| --- | --- |
| 何もしない | 自動では降ろさない |
| 空きが目標未満のときだけ必要な分をアンロード | 空きVRAMが **目標の空き（GB）** より少ないときだけ降ろす |
| 毎回すべてアンロード | 生成のたびに、必ずすべて降ろす |

> **ポイント**
> どれを選べばよいか迷ったら、「空きが目標未満のときだけ必要な分をアンロード」がおすすめです。
> 目標の空きには、画像生成に必要なメモリの量（使うモデルによって異なります）を目安に入力します。
> **今すぐすべてアンロード** ボタンで、その場ですぐに解放することもできます。

> **注意**
> この自動解放は、Ollamaだけが対象です。LM Studioなどを使っている場合は、手動で解放してください。

## 10-4 セキュリティ上の注意

### 標準では「自分のパソコン」のAIにだけつながる
安全のため、Workflow StudioがつなぐAIソフト（Ollama、LM Studioなど）は、標準では
**同じパソコンの中（localhost／127.0.0.1）で動いているもの** に限られています。

### 別のパソコンのAIを使いたいとき
家庭内LANにある別のパソコン（GPUの強いパソコンなど）でOllamaを動かして使いたい場合は、
環境変数 **`WFS_ALLOWED_BACKEND_HOSTS`** に、つなぎたいパソコンのアドレスを登録して、ComfyUIを再起動します。

```
WFS_ALLOWED_BACKEND_HOSTS=192.168.1.20:11434
```

複数ある場合は、カンマ（,）で区切って並べます。
環境変数の設定方法は、ComfyUIの起動方法によって異なります。

### ComfyUIを `--listen` 付きで起動している場合
ComfyUIを `--listen` オプション付きで起動すると、同じネットワークにいるほかのパソコンやスマホからも
ComfyUI（とWorkflow Studio）にアクセスできるようになります。
その場合、アクセスできる人なら誰でも、あなたのAIソフトや画像を使えてしまいます。

> **注意**
> `--listen` は、家庭内LANなど **信頼できるネットワークでだけ** 使ってください。
> カフェや公共のWi-Fiでは使わないようにしましょう。

## 10-5 スキル － Chatの得意分野を切り替える（v0.9.5〜）

**スキル** は、Chatに「どんな役割で、どんな形で答えるか」を教える指示書です。
Chatの上のドロップダウン（最初は「-- スキルなし --」）で選ぶと、そのスキルの指示が毎回の会話に付けて送られます
（指示の文章はチャットの画面には表示されません）。

### 最初から入っているスキル
Workflow Studioには、次の6つのスキルが入っています（名前は英語表示のままです）。

| スキル | 何をするか | 結果の使い方 |
| --- | --- | --- |
| T2I Prompt Enhancer | 短いアイデアを、生成UIのワークフローのモデルに合った書き方のプロンプトにする | プロンプトの下のボタン |
| Image to Prompt | TOOLSに入れた画像を再現するプロンプトを書く（画像を読み取れるモデルが必要） | プロンプトの下のボタン |
| Storyboard to Lab | 物語をシーンごとのプロンプトに分け、Labで連続生成できる形にする | **Labで開く** |
| Workflow Doctor | ワークフローの説明や、エラーの原因の相談にのる（10-7） | 文章で答える |
| SVG Icon Generator | 簡単なアイコンやイラストをSVG（ベクター画像）で描く | プレビューと **Galleryに保存** |
| Skill Creator | 質問に答えていくと、新しいスキルを作ってくれる（10-9） | **スキルとして保存** |

### プロンプトを作って、そのまま生成する（T2I Prompt Enhancer）
1. 生成UIに、使うワークフローを読み込みます。スキルはこのワークフローのモデルを見て、プロンプトの書き方を決めます。
2. AI TOOLのChatで、ドロップダウンから **T2I Prompt Enhancer** を選びます。
3. 「雨の夜の東京、ネオン、傘を持つ猫」のように、日本語で作りたい絵を書いて送信します。
4. 返事に、選んだ書き方（`Style:` の行）と、英語のプロンプトの枠が表示されます。その下のボタンで使います。

| ボタン | 動き |
| --- | --- |
| GenerateUIに反映 | 生成UIのポジティブ／ネガティブの欄に書き込む |
| このプロンプトで生成 | その場で生成し、チャットに画像を表示する |
| コピー | ポジティブプロンプトをコピーする |

モデルに合わせた書き方は、次のとおりです。

| 生成UIのモデル | プロンプトの書き方 |
| --- | --- |
| Qwen-Image、FLUX、Z-Image など | 英語の文章（ネガティブは、CFGが1前後なら空にする） |
| Illustrious、NoobAI、Pony など（SDXLのアニメ系） | Danbooruのタグ（品質タグから始める） |
| 写実系のSDXL、SD1.5 | 短い言葉をカンマで並べる |

> **ポイント**
> 「もっと夜らしく」「猫を2匹に」のように続けて頼むと、直したプロンプト全体を出し直します。

> **ポイント：今入っているプロンプトは渡さない**
> 生成UIに今入っているプロンプトは、ふだんはAIに渡しません。渡すと、小さなモデルが古いネガティブプロンプトなどを新しいプロンプトに混ぜてしまうためです。
> 「**今のプロンプトを改善して**」のように、今のプロンプトに触れて頼んだときだけ渡します。

### ストーリーボードから連続生成する（Storyboard to Lab）
1. 生成UIに、文章から画像を作る（T2I）ワークフローを読み込みます。
2. Chatで **Storyboard to Lab** を選び、「茶トラの子猫が朝目覚めて、庭で蝶を追いかけ、夕方に縁側で昼寝する。3シーンで」のように頼みます。
3. 返事に、シーンの一覧と **Labで開く（3シーン）** ボタンが表示されます。ボタンを押します。
4. 生成UIの **Lab**（第5章 5-7）が開き、まだ保存していないプランとして読み込まれます。
   T2Iモードになり、Batchがシーンの数に、Prompt列がシーンごとのキーフレームになります。KSampler列には、全シーン共通のシード（`Seed …`）が入ります。
5. 内容を確かめて **Run** を押します。残したいときは **Plan Save** で保存します。

> **ポイント**
> 登場人物の見た目（髪・服の色など）は、全シーンで同じ文章が入るように書かれ、シードも固定されます。
> そのため、シーンが変わっても同じキャラクターに見えやすくなります。

### 返事の自動チェック
プロンプトやSVGを出すスキルでは、Workflow Studioが返事の形を自動で確かめます。
プロンプトの枠が崩れている、SVGが閉じていない、といった問題があると、
点線の枠で「**自動チェック：…**」と表示し、AIに1回だけ直させます。
説明だけを頼んだときなど、プロンプトやSVGを出していない返事はそのままにします。

### スキルの管理（鉛筆ボタン）
ドロップダウンの右の鉛筆ボタンで、スキルの一覧が開きます。

- **＋ 新規** で新しいスキルを書く、各行の鉛筆ボタンで編集・削除する、**取り込み** で他のスキルを追加する（10-9）
- 最初から入っているスキルには **同梱** と表示されます。
  編集していない同梱スキルは、Workflow Studioを更新すると自動で新しい版になります。
  編集したスキルは自動では置き換わらず、新しい版があると **↻（更新）** ボタンが表示されます。
- スキルのファイルは `ComfyUI/user/default/Workflow-Studio/ai_skills/` に保存されます。

> **注意**
> ↻（更新）で新しい版に置き換えると、そのスキルに加えた編集は消えます。

## 10-6 生成した画像をチェックして直す（v0.9.5〜）

チャットから生成した画像が、頼んだとおりになっているかをAIに確かめさせる機能です。
足りないところがあれば、その点だけを直したプロンプトで描き直せます。

### 準備：判定用のモデル
チェックには、ふつうのチャット用モデルではなく、Ollamaの **意思決定モデル**（はい／いいえを確率で答えるモデル）を使います。
画像を読み取れるもの（作者の環境では `d3:4b`、`clef-flash`、`clef` で動作を確認）を、`ollama pull` で用意します。

> **ポイント：なぜ専用のモデルを使うのか**
> 作者の検証では、チャット用のモデルに画像を見せて「剣を持っているか」と聞くと、持っていないのに「はい」と答えることがありました。
> 意思決定モデルは「はい」の確率を数字で返すので、あいまいな答えを見分けられます。

1. AI TOOLの **設定** にある **CHAT 画像チェック** で、**判定モデル（Ollamaの意思決定モデル）** を選びます（一覧が空なら **更新**）。
2. **自動修正の回数** を選びます。最初は **0（ボタンで修正）** がおすすめです。
3. **設定を保存** を押します。

### 使い方
1. Chatの入力欄の下にある **画像をチェック** にチェックを入れます。
2. チャットから画像を生成します（AIの画像生成、または **このプロンプトで生成**）。
3. 画像の下に結果のカードが表示されます。AIが頼んだ内容を3〜8個の確認項目に分け、1つずつ確かめた結果です。

| 表示 | 意味 |
| --- | --- |
| ✔（満たしている） | 「はい」の確率が85％以上 |
| ?（はっきりしない） | 30〜85％ |
| ✘（満たしていない） | 30％未満 |

4. ✘や?があるときは **足りない点を直して再生成** を押します。満たしていない項目だけをAIに伝え、プロンプトを書き直して描き直します。

自動修正の回数を1〜3にすると、ボタンを押さなくても、その回数まで自動でくり返します。

> **ポイント：SVGもチェックできる**
> SVG Icon Generatorで描いたSVGも、画像にしてから「頼んだものに見えるか」「部品（くちばし・翼など）が描けているか」をチェックします。
> **分かりにくい部分を描き直させる** で直させられます。

> **注意**
> - チェックは完ぺきではありません。とくに「誰が何を身につけているか」の取り違えに弱いため、
>   人物が複数いるときは「帽子は女の子ではない」のような逆向きの確認項目を自動で加えて補っています。
> - 描き直しの上手さは、チャット用モデルの力しだいです。直らないときは、頼み方を変えるか、モデルを変えてください。
> - 判定モデルもGPUのメモリを使います（`d3:4b` で約6GB）。読み込んだあとは、1回のチェックが数秒です。

## 10-7 ワークフローの不具合を相談する（Workflow Doctor、v0.9.5〜）

**Workflow Doctor** は、生成UIに読み込んだワークフローの説明や、エラーの原因の相談にのるスキルです。
AIの知識だけに頼らず、送信するたびにWorkflow Studioが実際に確かめた次の内容をAIに渡します。

| 確かめる内容 | 例 |
| --- | --- |
| インストールされていないノード | ComfyUIが知らないノードの名前 |
| ComfyUIの一覧に無いファイル・設定値 | 見つからないモデルやLoRA（似た名前の候補も） |
| 線のつながり | つながっていない入力、存在しないノードへの線 |
| 直近の実行エラー | ComfyUIの履歴に残ったエラーの内容 |
| ComfyUIのログ | ログに出た最新のエラーの部分 |

### 使い方
1. 相談したいワークフローを生成UIに読み込みます（エラーの相談なら、一度実行してエラーを出しておきます）。
2. Chatで **Workflow Doctor** を選びます。
3. 「実行する前に問題がないか確認して」「さっきのエラーの原因は？」のように聞きます。

> **例**
> LoRAのファイルを別のフォルダに移したワークフローで聞くと、
> 「`temp\` のフォルダに指定されたファイルが見つからない。`Illustrious\` に同じ名前のファイルがある」と、直し方まで答えました。

> **ポイント**
> 確かめる内容は、送信のたびに作り直されます。直したあとは、もう一度聞いてみてください。

## 10-8 画像の文字を読み取る（OCR、v0.9.5〜）

TOOLSで、画像に写っている文字を読み取れます。読み取った文字は、そのまま翻訳やChatに送れます。

### 準備：OCR用のモデル
OCRには、チャット用とは別の、文字を読むのが得意なモデルを使います。Ollamaで用意してください。
作者の環境で、横書きと縦書きの日本語・英語がまじった画像を読ませた結果は次のとおりです。

| モデル | 時間 | 読み取り |
| --- | --- | --- |
| LightOnOCR-3（`maternion/LightOnOCR-3:4b`） | 約1秒（位置つきは約6〜8秒） | すべて読めた |
| PaddleOCR-VL（マンガ向けの版） | 約4秒 | すべて読めた |
| DeepSeek-OCR系 | 約14秒 | すべて読めた（いつも位置つき） |
| PaddleOCR-VL 1.6、GLM-OCR | 約11〜15秒 | 縦書きを読み落とした |

### 使い方
1. TOOLSに画像をドロップします。
2. 作業で **文字起こし（OCR）** を選びます。
3. **OCRモデル** を選びます。名前に「ocr」を含むOllamaのモデルが、向いている順に並びます（一覧が空なら ↻ を押します）。
4. **実行** を押します。読み取った文字が、結果の欄に1行ずつ表示されます。

> **ポイント：文字の位置を表示**
> **文字の位置を表示** にチェックを入れると、画像の上に番号つきの枠が重なり、どこの文字かが分かります。
> 枠をクリックすると、結果の欄の同じ行が選ばれます。
> 位置を返せるのは LightOnOCR と DeepSeek-OCR系だけです。ほかのモデルでは、このチェックは選べません。

> **ポイント**
> 結果が空だったり、同じ行がくり返されたりしたときは、自動で白黒（グレースケール）にして1回だけ読み直します。

## 10-9 スキルを自作・取り込む（上級、v0.9.5〜）

### Skill Creatorで作る
Chatで **Skill Creator** を選び、「〇〇が得意なスキルを作りたい」と話しかけます。
AIが1つずつ質問してくるので答えていくと、スキルの下書きができます。
返事の下の **スキルとして保存** を押すと、スキルの一覧に下書きが入った状態で開くので、確かめて保存します。
「このスキルの、ここがうまくいかない」と相談して、今あるスキルを直してもらうこともできます。

### スキルのファイルの中身
スキルは、テキストファイル（`.md`）です。先頭の `---` で囲んだ部分に名前と説明を書き、その下にAIへの指示を書きます。
先頭の部分の `metadata:` には、次の設定も書けます（書かなくてもかまいません）。

| 設定 | 意味 |
| --- | --- |
| `output` | `prompt` か `svg`。返事の形を自動でチェックし、ボタンを付ける |
| `tools` | `[]` にすると、AIが自分で画像生成を始めない |
| `temperature` | 答えのばらつき（0.3なら安定、0.9なら自由） |
| `think` | 考える（Thinking）モードを、このスキルだけオン／オフにする |
| `context` | AIに渡す情報。`workflow`（ワークフローの要約）、`current-prompt`（今のプロンプト）、`workflow-detail`／`logs`（Workflow Doctorと同じ確認内容） |

### ほかのスキルを取り込む
スキルの一覧の **取り込み** で、次のファイルを追加できます。

- `.md` のスキル1つ
- `SKILL.md` を含むフォルダをZIPにしたもの（**Agent Skills** という、多くのAIツールで共通の形式）

フォルダの中のテキストファイル（参考資料など）も一緒に取り込まれ、AIが必要になったときだけ読みに行きます
（ツール呼び出しに対応したモデルが必要です）。

> **注意**
> - 取り込むのはテキストファイルだけです。スクリプトなどのプログラムは取り込まず、実行もしません。
> - スキルの指示は、そのままAIに渡されます。他の人が作ったスキルは、中身を読んでから使ってください。

> **この章のまとめ**
> - ローカルAI（Ollamaなど）を用意すると、翻訳・チャット・画像の読み取りができる。入力内容は外部に送られない
> - AI TOOLタブの設定で、バックエンド・アドレス・モデルを選び、接続テストをする
> - プロンプトタブとTaggerタブには、別に歯車ボタンの設定がある
> - AIと画像生成はVRAMを取り合う。「モデルをアンロード」や「VRAM調整（Ollama）」で解放する
> - 標準では自分のパソコンのAIにだけつながる。`--listen` は信頼できるネットワークだけで
> - **スキル** で得意分野を切り替える。T2I Prompt Enhancer でプロンプトを作り、ボタンで生成UIに反映・生成できる
> - **画像をチェック** をオンにすると、意思決定モデルが生成画像を確かめ、足りない点だけ直して描き直せる
> - Workflow Doctor は、実際に確かめた事実をもとにワークフローの不具合を相談にのる
> - TOOLSの **文字起こし（OCR）** で画像の文字を読み取り、翻訳やChatへ送れる
