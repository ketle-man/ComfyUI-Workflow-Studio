「ネットで拾ったワークフローが増えすぎて、どれが何だか分からない」

## ComfyUIは、なぜ難しいのか

ComfyUIは、いま最も自由度の高い画像生成AIソフトの1つです。
新しいモデルや技術が発表されると、真っ先に使えるようになるのは、たいていComfyUIです。
それなのに、多くの人が最初の一歩でつまずいてしまいます。その理由は、ComfyUIが **普通のアプリケーションとはまったく違う考え方** で作られているからです。

### 普通のアプリケーションとの違い
| | 普通のアプリケーション | ComfyUI |
| --- | --- | --- |
| 画面 | 開発者が設計した、決まった画面 | ノード（箱）を線でつないで、自分で組み立てる |
| 使い方 | ボタンやメニューを押せば動く | どのノードを、どうつなぐかを知らないと動かない |
| 機能の追加 | アップデートを待つ | 誰かが作ったカスタムノードを、自分で追加する |
| 設定の場所 | 設定画面にまとまっている | ワークフローの中の、あちこちのノードに散らばっている |

普通のアプリケーションは、言わば「完成品の家電」です。電源を入れれば、決められた使い方ですぐに使えます。
一方のComfyUIは、「部品から組み立てる工作キット」です。
組み立て方さえ分かれば、どんなものでも作れますが、組み立て方を知らなければ何も作れません。

### 自由さと、その副作用
ComfyUIの最大の魅力は、この **カスタマイズの自由さ** です。
世界中の開発者が作ったカスタムノードを組み合わせて、自分だけの処理の流れ（ワークフロー）を作れます。
ネットには、上級者が作った高度なワークフローがたくさん公開されていて、ダウンロードすればすぐに試せます。

しかし、自由さには副作用もあります。

- **ワークフローが増えすぎる** － 試したいものを次々ダウンロードするうちに、どれが何だか分からなくなる
- **どこを触ればいいか分からない** － 他人が作った大きなワークフローは、プロンプトを変えたいだけでも、該当するノードを探すのに苦労する
- **素材がバラバラになる** － モデル・LoRA・プロンプト・生成画像が、それぞれ別の場所に散らばり、管理する道具がない
- **試行錯誤に手間がかかる** － 条件を少しずつ変えて比べたいだけでも、1回ごとにノードの値を書き換える必要がある

ComfyUIは「組み立てる」ための道具としては非常に優秀ですが、
「整理する」「繰り返し使う」「手軽に試す」ための道具は、ほとんど用意されていません。
この空白を埋めるために作られたのが、Workflow Studioです。

## Workflow Studioの特色

### 1. なぜ専用画面（SPA）なのか － 「組み立てる」と「使う」を分ける
Workflow Studioは、ComfyUIの上部メニューの **W** ボタンから開く、**独立した専用画面**（SPA：シングルページアプリケーション）です。

ワークフローを組み立てる作業は、ComfyUIのノード画面で試行錯誤するのがいちばんです。
Workflow Studioは、そうして作り上げたワークフローを **素早く活用する** ための画面として生まれました。

そのため、Workflow Studioはワークフローを **入力・処理・出力** の3つに分けて考え、次のように設計されています。

| 段階 | 設計の考え方 |
| --- | --- |
| 入力 | プロンプトや画像を入れやすくする |
| 処理 | 値の変更は、最小限の操作で済むようにする |
| 出力 | 生成されたデータを管理しやすくする |

設計の根底には、製造現場などで使われる **5S（整理・整頓・清掃・清潔・しつけ）** の考え方があります。
必要なものを、必要なときに、すぐ取り出して使える状態を保つことを目指しています。

そして、ComfyUIのノード画面とWorkflow Studioの2つの画面をつなぐのが、ノード画面の横に開く **WS Library** です。
補助機能とあわせて、2つの画面を行き来する作業をスムーズにします。

### 2. 管理 － 散らばった素材を1か所に
| 管理できるもの | できること |
| --- | --- |
| ワークフロー | サムネイル付きの一覧、バッジ・グループで分類、検索、生成UIで動くかの事前チェック |
| モデル・LoRA | 種類ごとの一覧、Civitaiからの情報（トリガーワード・サンプル画像）の自動取得 |
| プロンプト | プリセットとして保存・分類、ワイルドカード、スタイル |
| 生成画像・音声 | フォルダごとの閲覧、プロンプトや「意味」での検索、埋め込まれた設定の読み取りと再現（音声ファイルにも対応） |

### 3. 効率化 － ノードを触らずに、すばやく試す
- **生成UIタブ** － ワークフローの中から、プロンプト・モデル・サイズなど、よく変える項目だけを自動で取り出し、入力フォームにします。他人が作った大きなワークフローでも、ノードを探さずに使えます
- **バッチ生成** － 「手持ちのモデルを全部試す」「プロンプトを順番に試す」「サンプラーを比べる」といった試行錯誤を、まとめて自動で実行します
- **Feeder・Lab** － たくさんの画像を順番に処理したり、複数の条件を段階的に切り替えたりする、さらに進んだ自動化もできます

### 4. 補助機能 － 生成の前後を手助けする
- **画像編集（Image Edit）** － レイヤー付きの簡易編集、マスクを使った部分的な描き直し（インペイント）
- **ローカルAI連携** － 日本語からのプロンプト翻訳、画像からのプロンプト・タグ作成
- **Tagger・Video** － 画像からのタグ自動生成、動画の生成と簡単な編集

## インストールして損のないカスタムノード

Workflow Studioは、次の理由から、ComfyUIを使うすべての人に **「とりあえず入れておいて損はない」** カスタムノードだと言えます。

- **無料で、ComfyUI Managerからすぐに入れられる**
- **基本機能に、追加の準備がいらない** － 必要なものはComfyUIに最初から含まれています。AIや画像編集などの追加機能は、使いたくなったときに準備すれば十分です
- **今の使い方を変えなくていい** － ワークフローはComfyUIの保存フォルダをそのまま使います。ノード画面での作業も、これまでどおりできます
- **使った分だけ便利になる** － ワークフローを一覧で眺めるだけ、生成画像の設定を確かめるだけ、といった使い方から始めて、慣れてきたら生成UIやバッチ生成へと、少しずつ活用の幅を広げられます

ComfyUIの「自由さ」はそのままに、「分かりやすさ」と「手軽さ」を足してくれる － それがWorkflow Studioです。

# 第1章 ComfyUIとWorkflow Studioの基礎知識

この章では、操作を始める前に知っておきたい考え方と言葉を整理します。
パソコンを触りながら読む必要はありません。通勤中やすきま時間に、気軽に読み進めてください。

---

## 1-1 ComfyUIってなに？

ComfyUI（コンフィーユーアイ）は、画像生成AIを自分のパソコンで動かすための無料ソフトです。
Stable Diffusion や FLUX など、さまざまな画像生成AIのモデルに対応しています。

ComfyUIのいちばんの特徴は、**処理の流れを「箱」と「線」でつないで組み立てる**ことです。

「モデルを読み込む箱」→「プロンプトを入れる箱」→「画像を作る箱」→「保存する箱」……
というように、箱どうしを線でつなぐと、その順番で処理が行われます。

この方式には、大きなメリットがあります。

- 処理の中身がすべて見えるので、細かく調整できる
- 新しい技術が出ても、箱を追加するだけで試せる
- 組み立てた流れを保存して、何度でも使い回せる

一方で、はじめて触る人にとっては「どこを触ればいいのか分からない」画面でもあります。
この本で紹介する **Workflow Studio** は、まさにその「分かりにくさ」をやわらげるための道具です。

---

## 1-2 覚えておきたい5つの言葉

ComfyUIを使ううえで、最低限知っておきたい言葉は次の5つです。

### ① ノード（Node）
画面上に並ぶ「箱」のことです。
1つのノードは1つの仕事を受け持ちます。たとえば「モデルを読み込む」「画像を保存する」などです。
ノードには入口（入力）と出口（出力）があり、線でつないでデータを受け渡します。

### ② ワークフロー（Workflow）
ノードを線でつないだ「処理の流れ全体」のことです。
料理にたとえると、ノードが「切る」「炒める」などの作業で、ワークフローは「レシピ」にあたります。
ワークフローはJSON（ジェイソン）という形式のファイルで保存できます。

> **ポイント**
> ComfyUIで作った画像には、多くの場合ワークフローの情報が埋め込まれています。
> その画像をComfyUIの画面にドラッグすると、同じワークフローを呼び出せます。

### ③ モデル（Model）
画像を作る「AIの頭脳」にあたるファイルです。数GB〜数十GBと大きいのが一般的です。
代表的なものに次の種類があります（詳しくは第6章で説明します）。

| 種類 | ひとことで言うと |
| --- | --- |
| Checkpoint（チェックポイント） | 画像生成の本体となるモデル |
| LoRA（ローラ） | 絵柄やキャラクターを追加で覚えさせる小さな追加モデル |
| VAE | 画像の色合いや細部の仕上げを担当するモデル |

### ④ プロンプト（Prompt）
AIに「どんな画像を作ってほしいか」を伝える文章です。いわゆる「呪文」です。
描いてほしいものを書く **ポジティブプロンプト** と、
描いてほしくないものを書く **ネガティブプロンプト** の2種類があります。

### ⑤ キュー（Queue）
「生成の予約リスト」のことです。
ComfyUIでは、生成ボタンを押すとまずキューに予約が入り、順番に処理されます。
何枚分も予約しておけば、席を外している間にまとめて生成してくれます。

## 1-3 ComfyUIで初心者がつまずくところ

ComfyUIを入れてみたものの、こんなところで手が止まっていませんか。

1. **ワークフローが増えて、どれが何だか分からない**
   ネットで拾ったワークフローを保存していくうちに、ファイル名だけでは見分けがつかなくなります。

2. **毎回ノード画面で値を探すのが大変**
   プロンプトやシード値を変えたいだけなのに、大きなワークフローの中から該当するノードを探す必要があります。

3. **モデルやプロンプトの管理がバラバラ**
   どのモデルをどこに置いたか、前にうまくいったプロンプトは何だったか……が分からなくなりがちです。

4. **前に作った画像の設定を再現できない**
   「あの画像、どの設定で作ったっけ？」となっても、調べ方が分からないことがあります。

どれも、ComfyUIの機能が足りないというより、**「整理」と「入口」が足りない**ことが原因です。

---

## 1-4 Workflow Studioでできること

Workflow Studioは、ComfyUIに追加して使う **拡張機能（カスタムノード）** です。
ComfyUIの中に「管理と生成のための専用画面」を追加してくれます。

先ほどの4つのつまずきに対して、Workflow Studioは次のように応えます。

| つまずき | Workflow Studioの解決策 | 本書の章 |
| --- | --- | --- |
| ワークフローが見分けられない | サムネイル付きの一覧、バッジ・グループ分け、検索 | 第4章 |
| ノード画面で値を探すのが大変 | 「生成UI」タブで、必要な項目だけをフォームとして表示 | 第5章 |
| モデル・プロンプトがバラバラ | モデルタブ・プロンプトタブでまとめて管理 | 第6・7章 |
| 設定を再現できない | ギャラリーで画像のメタデータを確認し、キャンバスへ送る | 第8章 |

さらに、ComfyUIのノード画面の横に **WS Library** というサイドパネルが追加され、
モデルやプロンプトをドラッグ＆ドロップでノード画面に置けるようになります（第9章）。

ローカルで動くAI（OllamaやLM Studioなど）を用意すれば、
プロンプトの翻訳や、画像からのタグ生成といったAI補助も使えます（第10章）。

> **ポイント**
> Workflow Studioは、ComfyUIの代わりになるソフトではありません。
> 画像を作るのはあくまでComfyUIで、Workflow Studioはその「操作パネル」と「整理棚」の役割です。
> そのため、ComfyUIが起動していないと使えません。

### 画面は日本語で使えます
Workflow Studioは英語・日本語・中国語に対応しています。
本書では日本語表示の画面で説明し、必要に応じて英語表示の名前を（ ）で添えます。

例：「生成UI（GenerateUI）」タブ、「ワークフロー（Workflow）」タブ

## 2-2 ComfyUI Managerでインストールする（おすすめ）

**ComfyUI Manager** は、カスタムノード（拡張機能）を画面上から検索・インストールできる管理ツールです。
最近のComfyUIには最初から入っていることが多く、いちばん手軽な方法です。

1. ComfyUIを起動し、ブラウザで画面を開きます。
2. 上部メニューの **「Manager」** ボタンをクリックします。

3. **「Custom Nodes Manager」** をクリックします。
4. 検索欄に **`Workflow Studio`** と入力します。
5. 一覧に表示された **ComfyUI-Workflow-Studio** の **「Install」** をクリックします。

6. インストールが終わったら、画面の案内に従って **ComfyUIを再起動** します。

> **注意**
> ComfyUIは、起動したときに一度だけ拡張機能を読み込みます。
> インストール後は必ずComfyUIを再起動してください。ブラウザの再読み込みだけでは反映されません。

## 2-3 手動でインストールする（git clone）

ComfyUI Managerが使えない場合や、Gitに慣れている方は、手動でもインストールできます。
コマンドを入力する画面（Windowsなら「コマンドプロンプト」や「ターミナル」）を使います。

1. ComfyUIのフォルダの中にある **`custom_nodes`** フォルダに移動します。

   ```

   ```


3. `custom_nodes` の中に **`ComfyUI-Workflow-Studio`** フォルダができていればOKです。
4. ComfyUIを再起動します。

> **ポイント**
> `git` コマンドが使えない場合は、Git（Git for Windowsなど）を先にインストールする必要があります。
> 不安な方は、2-2のComfyUI Managerを使う方法がおすすめです。

## 2-4 起動する

### Wボタンから開く
ComfyUIを再起動すると、画面上部のメニューに **「W」** のボタンが追加されています。
これがWorkflow Studioを開くボタンです。

- **クリック** － 新しいタブでWorkflow Studioが開きます。
- **Shiftキーを押しながらクリック** － 新しいウィンドウで開きます。ComfyUIの画面と並べて使いたいときに便利です。

Wボタンの近くには、**カメラのボタン** も追加されています。
これは、ワークフローの画面をサムネイルとして保存するためのボタンです（第4章で使います）。

### アドレスとポート番号のしくみ
Wボタンを押すと、ブラウザのアドレス欄にWorkflow Studioのアドレスが表示されます。
このアドレスの見方を知っておくと、ブックマークから直接開いたり、トラブルのときに原因を探したりできます。

アドレスは、次の3つの部分でできています。

| 部分 | 例 | 意味 |
| --- | --- | --- |
| ホスト | `127.0.0.1` | どのパソコンにつなぐか。`127.0.0.1`（または `localhost`）は「自分のパソコン」を表す特別な番号です |
| ポート番号 | `8188` | そのパソコンの中の、どのソフトにつなぐか |
| パス | `/wfm` | そのソフトの中の、どのページを開くか |

この3つを「`ホスト:ポート番号/パス`」の形でつなげたものが、Workflow Studioのアドレスになります。

#### ポート番号とは
1台のパソコンの中では、たくさんのソフトが同時に通信しています。
そこで、どのソフトあての通信なのかを区別するために使われるのが **ポート番号** です。

マンションにたとえると、ホスト（`127.0.0.1`）が「建物の住所」、ポート番号が「部屋番号」にあたります。
同じ建物でも、部屋番号を間違えると目的の相手には届きません。

ComfyUIは、起動したときに決められたポート番号で待ち受けています。
よく使われる番号は次のとおりです。

| ComfyUIの種類・起動方法 | よく使われるポート番号 |
| --- | --- |
| ポータブル版・手動インストール版（標準設定） | 8188 |
| ComfyUI Desktop（デスクトップアプリ版） | 8000 |
| 起動オプション `--port` を指定した場合 | 指定した番号 |

Stability Matrixなどのランチャーを使っている場合も、ランチャー側の設定で番号が変わることがあります。

#### 自分のポート番号を確かめる
いちばん確実なのは、**いまComfyUIを開いているブラウザのアドレス欄を見る** ことです。
`127.0.0.1:` や `localhost:` のあとに続く数字が、ポート番号です。

ComfyUIを起動したときの黒い画面（コンソール）にも、
`To see the GUI go to: http://127.0.0.1:〇〇〇〇` のように表示されます。

#### アドレスを直接入力して開く
ポート番号が分かれば、Wボタンを使わずにWorkflow Studioを開けます。
ComfyUIのアドレスの末尾に **`/wfm`** を付けるだけです。

- ComfyUIが `127.0.0.1:8188` で開いている → Workflow Studioは `127.0.0.1:8188/wfm`
- ComfyUIが `127.0.0.1:8000` で開いている → Workflow Studioは `127.0.0.1:8000/wfm`

よく使う方は、このアドレスをブックマークしておくと便利です。

> **注意**
> ブックマークから開いた場合、ワークフローをComfyUIのキャンバスへ直接送る「Send to Canvas」が使えません。
> 代わりに、ComfyUI側のサイドパネル（WS Library）にそのワークフローが表示されるので、自分でキャンバスへドラッグします（第4章・第9章）。
> ComfyUIの画面と行き来しながら使うときは、Wボタンから開くのがおすすめです。

> **ポイント**
> Workflow StudioはComfyUIの一部として動いているため、ComfyUIと同じポート番号を使います。
> Workflow Studio専用のポート番号はありません。

## 2-5 表示言語を日本語にする

Workflow Studioは、はじめは **英語** で表示されます。次の手順で日本語に切り替えましょう。

1. 上部のタブから **「Settings」** を開きます。
2. **「UI Language」** の欄で **「日本語」** を選びます。

3. 「言語を変更しました。再読み込みします...」という表示のあと、ページが自動で再読み込みされ、日本語表示に切り替わります。

日本語に切り替えると、タブの名前は次のように変わります（一部は英語のままです）。

| 英語表示 | 日本語表示 |
| --- | --- |
| Workflow | ワークフロー |
| GenerateUI | 生成UI |
| Gallery | ギャラリー |
| Prompt | プロンプト |
| Models | モデル |
| Nodes | ノード |
| Settings | 設定 |
| Help | ヘルプ |
| AI TOOL / Tagger / Image Edit / Video | （英語のまま） |

> **ポイント**
> 言語の設定は、使っている **ブラウザごと** に保存されます。
> 別のブラウザや別のパソコンから開いた場合は、もう一度設定してください。

同じ場所にある **「要約言語」** は、AIでワークフローの説明文を作るときの言語です（第10章）。今は変更しなくてかまいません。

## 2-6 環境ごとのフォルダの場所

ComfyUIには、いくつかの入れ方があります。入れ方によって、フォルダの場所が少しずつ違います。
本書では、フォルダの場所を **`ComfyUI/` から始まる形** で書いています。
お使いの環境に合わせて、下の表の「`ComfyUI/` にあたる場所」に読み替えてください。

### 本書の書き方と、各環境での場所

| `ComfyUI/custom_nodes/` | カスタムノード（Workflow Studioもここ） | `ComfyUI/custom_nodes/` | `ComfyUI/custom_nodes/` | `ComfyUI/custom_nodes/` |
| `ComfyUI/models/` | モデル | `ComfyUI/models/` | `ComfyUI/models/` | `（データフォルダ）/Models/`（全パッケージで共有） |

| 標準のポート番号 | 2-4参照 | 8188 | 8000 | 8188 |

> **ポイント**
> 表の中の `ComfyUI/` は、それぞれの環境の「`ComfyUI/` にあたる場所」を指します。
> パスの区切りは、Windowsでは `/` の代わりに `\` で表示されます。

### ポータブル版
ダウンロードしたZIPファイルを展開してできた `ComfyUI_windows_portable` フォルダの中に、すべてが入っています。
起動は、フォルダ内の `run_nvidia_gpu.bat` などで行います。
**Python** は、ComfyUI専用の `python_embeded` フォルダの中のものを使います（第11章 11-2）。

### ComfyUI Desktop
インストーラーで入れるアプリ版です。最初の起動時に、データを置くフォルダを選びます。
フォルダの場所を忘れたときは、アプリのメニューからフォルダを開く項目（「Open Folder」など）を使うと確認できます。
標準のポート番号が **8000** なので、アドレスを直接入力するときは注意してください（2-4）。

### Stability Matrix
複数の画像生成ソフトをまとめて管理できるランチャーです。
最初に決めた **データフォルダ**（例：`StabilityMatrix/Data/`）の中に、次のように分かれて入っています。

- **ComfyUI本体** － `Data/Packages/ComfyUI/`
- **モデル** － `Data/Models/` の中に、種類ごとのフォルダ（Checkpointは `StableDiffusion`、LoRAは `Lora` など）。ほかのソフトと共有されます
- **生成した画像** － `Data/Images/` の中

> **注意**
> Stability Matrixでは、モデルや画像のフォルダが **ComfyUIの本体フォルダの外** にあります。
> 本書で「`ComfyUI/models/checkpoints` に置く」と書いてある場合は、Stability Matrixの共有モデルフォルダ（`Data/Models/StableDiffusion` など）に置いてください。
> ギャラリーに画像が出てこないときは、設定タブの「ギャラリー Outputフォルダ」が `Data/Images/` の中を指しているか確認しましょう。

> **ポイント**
> フォルダの名前や構成は、各ソフトのバージョンアップで変わることがあります。
> 見つからないときは、各ソフトの公式の説明も確認してください。

## 2-7 うまく起動しないときは

### Wボタンが表示されない
- **ComfyUIを再起動しましたか？** ブラウザの再読み込みだけでは反映されません。
- **インストール先は正しいですか？** `ComfyUI/custom_nodes/ComfyUI-Workflow-Studio` にフォルダがあるか確認してください。
  フォルダの中にさらに同じ名前のフォルダがある（二重になっている）と読み込まれません。
- **ComfyUIのバージョンが古くありませんか？** ComfyUI Managerなどから本体を更新してみてください。

### ページが開かない・「接続できません」と表示される
- **ComfyUIは起動していますか？** Workflow StudioはComfyUIの中で動くため、ComfyUIを終了すると開けません。
- **ポート番号は合っていますか？** 2-4の方法で、ComfyUIのポート番号を確認してください。
  たとえばComfyUI Desktopを使っているのに `8188` を入力していると、つながりません。

### 起動時のコンソールにエラーが出る
ComfyUIを起動したときの黒い画面に、`ComfyUI-Workflow-Studio` に関するエラーが表示されていないか確認します。
エラーの内容をメモしておくと、第12章のトラブルシューティングや、GitHubで質問するときに役立ちます。

> **この章のまとめ**
> - インストールはComfyUI Managerで「Workflow Studio」を検索するのがかんたん
> - インストール後は必ずComfyUIを再起動する
> - 上部メニューの「W」ボタンで開く（Shift＋クリックで別ウィンドウ）
> - アドレスは「ホスト:ポート番号/wfm」。ポート番号はComfyUIを開いているアドレス欄で確認できる
> - 設定タブの「UI Language」で日本語に切り替える
> - フォルダの場所は環境（ポータブル版・Desktop・Stability Matrix）によって違う。本書の `ComfyUI/` は読み替える

タブが多くて迷ったときは、次の3つのグループに分けて考えると分かりやすくなります。

- **整理する** － ワークフロー／ノード／モデル／プロンプト／ギャラリー

## 3-3 サイドパネル「WS Library」

③のボタンを押すと、ComfyUIのノード画面の横に **WS Library（Workflow Studio Library）** というパネルが開きます。

WS Libraryは、**Workflow Studioで整理した素材を、ノード画面ですぐ使うための棚** です。
パネルの上部には、1文字のタブが並んでいます（マウスを重ねると正式な名前が表示されます）。

| タブ | 名前 | できること |
| --- | --- | --- |
| W | Workflows | ワークフローをドラッグしてキャンバスに読み込む |
| N | Nodes | お気に入りのノードやノードセットをキャンバスに置く |
| P | Prompts | 保存したプロンプトをキャンバスに置く・コピーする |
| M | Models | モデルをドラッグして、読み込み用のノードごとキャンバスに置く |
| I | Information | 画像やワークフローのファイルを落として、中身（使ったモデルやプロンプト）を調べる |
| A | AI TOOL | 翻訳やチャットなどのAI機能を、ノード画面のまま使う |

たとえば M タブからモデルをキャンバスへドラッグすると、そのモデルを読み込むノードが自動で配置されます。
ノードを一覧から探して置いて、ファイル名を選んで……という手間が省けます。

詳しい使い方は第9章で説明します。今は「ノード画面の横に、素材の棚を出せる」とだけ覚えておけば大丈夫です。

## 3-4 テーマと見た目の設定

Workflow Studioの見た目は、**設定** タブで好みに合わせて変えられます。
長時間使う道具なので、目が疲れにくい配色や読みやすい文字サイズにしておくのがおすすめです。

### テーマ
**「テーマ」** の欄から、画面全体の配色を選べます。標準は暗い配色の「Deep Ocean Dark」です。

| テーマの例 | 雰囲気 |
| --- | --- |
| Deep Ocean Dark（デフォルト） | 暗めの青。画像が見やすい |
| Light Minimalist（クリーン） | 白基調で明るくシンプル |
| Pastel Dream（パステル） | やわらかいパステル調 |
| Corporate Trust（企業向け） | 落ち着いた白と青 |

このほか、ポップ調・サイバーパンク・レトロなど、全部で13種類のテーマがあります。

> **ポイント**
> 生成した画像の色を確認するときは、暗めのテーマのほうが色を見分けやすくなります。
> 迷ったら、まずはデフォルトのまま使ってみましょう。

### カスタマイズ
**「カスタマイズ」** を開くと、選んだテーマをさらに細かく調整できます。

- **カラー調整** － 背景・テキスト・アクセントなどの色を個別に変更
- **背景パターン** － ストライプやドットなどの模様を背景に追加
- **フォント** － 文字の書体を変更（Zen丸ゴシック、BIZ UDPゴシックなど日本語フォントも選べます）

調整が終わったら **「適用して保存」** を押します。
元に戻したいときは **「カスタマイズをリセット」** を押します。

### 文字サイズ
**「文字サイズ」** の欄で、画面全体の文字の大きさを変えられます。
文字が小さくて読みにくいと感じたら、ここで大きくしましょう。

### WS Libraryの見た目
WS Library（3-3）の配色は、パネル内の **歯車ボタン**から別に設定できます。
ComfyUIの画面の色に合わせて、背景や文字の色を調整できます。

> **この章のまとめ**
> - タブは「整理する」「作る」「補助する」の3グループで考えると分かりやすい
> - まずはワークフロー・モデル・生成UI・プロンプト・ギャラリーの5つを覚えれば十分
> - ComfyUIの上部には「W」「カメラ」「WS Library」の3つのボタンが追加される
> - WS Libraryは、ノード画面の横に出せる素材の棚
> - 見た目は設定タブのテーマ・カスタマイズ・文字サイズで調整できる

# 第4章 ワークフロータブ － 作ったワークフローを整理する

ワークフロータブは、Workflow Studioを開いたときに最初に表示される、いわば「玄関」です。
この章では、手持ちのワークフローを一覧で見られるようにし、
あとから探しやすいように整理する方法を学びます。

---

## 4-1 ワークフローが自動で一覧表示されるしくみ

ワークフロータブを開くと、すでにいくつかのワークフローが並んでいるかもしれません。
これは、Workflow StudioがComfyUIのワークフロー保存フォルダを自動で読み込んでいるためです。

ComfyUIのノード画面で「保存（Save）」したワークフローは、通常、次のフォルダに保存されます。

```
ComfyUI/user/default/workflows/
```

Workflow Studioは、このフォルダの中のワークフローを一覧にして表示します。
つまり、**ComfyUIで保存したワークフローは、何もしなくてもワークフロータブに並ぶ** というわけです。

> **ポイント**
> ComfyUIで新しく保存したワークフローが一覧に出てこないときは、
> ツールバーの **「更新」** ボタンを押してください。最新の状態に読み込み直します。

> **ポイント**
> 読み込むフォルダは、設定タブの **「ワークフローデータフォルダ」** で変更できます。
> 特に理由がなければ、そのままで問題ありません。

---

## 4-2 画面の見方と表示の切り替え

ワークフロータブは、大きく3つの部分に分かれています。

| 番号 | 場所 | 役割 |
| --- | --- | --- |
| ① | ツールバー（上部） | 検索・絞り込み・並べ替え・各種ボタン |
| ② | 一覧（中央） | ワークフローがカードまたは表で並ぶ |
| ③ | サイドパネル（右側） | 選んだワークフローのサムネイルや中身を表示 |

### サムネイル表示とテーブル表示
ツールバーの切り替えボタンで、一覧の表示方法を変えられます。

- **サムネイル** － 画像付きのカードで並べます。見た目で探したいときに便利です。
- **テーブル** － 表形式で並べます。たくさんのワークフローを名前で探したいときに便利です。

### クリックとダブルクリック
一覧のワークフローは、クリックの仕方で動きが変わります。

| 操作 | 動き |
| --- | --- |
| クリック | 右側のサイドパネルに内容を表示（ワークフローを「選択」した状態になる） |
| ダブルクリック | 詳細画面を開く（バッジ・タグ・メモの編集など。4-4で説明） |

### サイドパネル
ワークフローをクリックすると、右側のサイドパネルに次の3つのタブが表示されます。

- **サムネイル** － ワークフローの画像を大きく表示
- **JSON** － ワークフローの中身（JSONデータ）を色分けして表示。「コピー」ボタンで丸ごとコピーできます
- **グループ** － ワークフローをグループに分類（4-4で説明）

ワークフロー名の下には、**ワークフローの形式**（UI形式／API形式など）と、
生成UIで使えるかどうかの **チェック結果** が表示されます（4-7で説明）。

## 4-3 カメラボタンでサムネイルを撮る

ComfyUIで保存しただけのワークフローは、サムネイル画像がなく、一覧では見分けにくいことがあります。
そこで使うのが、ComfyUIの上部メニューに追加された **カメラボタン**（キャンバススナップショット）です。

### サムネイルの撮り方
1. ComfyUIのノード画面で、サムネイルにしたいワークフローを開きます。
2. ワークフロー全体が見やすくなるように、画面の位置や拡大率を調整します。
3. 上部メニューの **カメラボタン** をクリックします。

4. 保存する名前を確認する画面が表示されます。必要に応じて名前を変えて保存します。
   （最初は、いま開いているワークフローの名前が入っています）
5. 「Workflow saved」と表示されれば完了です。

Workflow Studioのワークフロータブを開く（または「更新」を押す）と、
撮影した画像がサムネイルとして付いたワークフローが一覧に表示されます。

> **ポイント**
> カメラボタンで保存した画像（PNG）には、ワークフローの情報も埋め込まれています。
> この画像をComfyUIのノード画面にドラッグ＆ドロップすると、そのワークフローを読み込めます。
> 画像ファイル1つで「見た目」と「中身」の両方を持ち運べるので便利です。

### あとからサムネイルを変える
すでにあるワークフローのサムネイルを差し替えたいときは、
ワークフローをダブルクリックして詳細画面を開き、**「サムネイル変更」** を押して画像を選びます。

## 4-4 お気に入り・バッジ・グループで分類する

ワークフローが増えてきたら、分類しておくと目的のものをすぐに見つけられます。
Workflow Studioには、分類のしかたが3種類あります。

| 方法 | どんなときに使う？ | 例 |
| --- | --- | --- |
| お気に入り（★） | よく使うものに印を付けたい | 毎日使う基本のワークフロー |
| バッジ | 色付きのラベルで、ひと目で種類を分けたい | 「SDXL」「FLUX」「動画」「実験中」 |
| グループ | 用途やプロジェクトごとにまとめたい | 「キャラクター制作」「背景素材」 |

### お気に入り（★）
カードの **★** をクリックすると、お気に入りに登録されます。
ツールバー上部の **★** ボタンを押すと、お気に入りだけを表示できます（**ALL** で全件表示に戻ります）。

お気に入りに登録したワークフローは、ComfyUI側のサイドパネル（WS Library）の
「★ Favorites」にも表示されます（第9章）。

### バッジ
バッジは、ワークフローに付ける **色付きのラベル** です。
1つのワークフローに複数のバッジを付けることもできます。

**① バッジを作る**
1. ツールバーの **「Badge」** ボタンを押します。
2. **「バッジ名...」** の欄に名前を入力し、**「追加」** を押します。
3. 色の見本をクリックすると、バッジの色を変えられます。

**② ワークフローにバッジを付ける**
1. ワークフローをダブルクリックして、詳細画面を開きます。
2. **「バッジ」** の欄で、付けたいバッジにチェックを入れます。
3. **「保存」** を押します。

**③ バッジで絞り込む**
バッジを作ると、ツールバー上部の ★・ALL ボタンの横にバッジが並びます。
バッジをクリックすると、そのバッジが付いたワークフローだけが表示されます。

> **ポイント**
> バッジの種類と色は、モデルタブ（第6章）と共通です。
> 「SDXL」というバッジを作れば、ワークフローにもモデルにも同じ色で付けられます。

### グループ
グループは、ワークフローを **用途ごとにまとめる箱** です。

1. ワークフローをクリックして選択します。
2. 右側のサイドパネルで **「グループ」** タブを開きます。
3. **「新規グループ作成」** でグループを作るか、既存のグループを選んで **「グループに追加」** します。

ツールバーの **「全グループ」** と書かれたプルダウンからグループを選ぶと、そのグループのワークフローだけが表示されます。

### タグとメモ
詳細画面では、ほかにも次の情報を書き込めます。

- **タグ** － 検索用のキーワード。カンマ（,）で区切って複数入力できます。
- **メモ** － 使い方の注意点や、うまくいった設定など、自由なメモ。

ネットから入手したワークフローに「配布元」や「必要なカスタムノード」をメモしておくと、あとで困りません。

### 名前の変更と削除
- **名前を変える** － 詳細画面の上部にあるワークフロー名をクリックすると、名前を編集できます。
- **削除する** － 詳細画面の **「削除」** ボタンを押します。

> **注意**
> 削除すると、ComfyUIのワークフロー保存フォルダにあるファイルそのもの（サムネイル画像も含む）が削除されます。
> 大切なワークフローは、削除する前に別の場所へバックアップしておきましょう。

## 4-5 検索・並べ替え・フィルタ解除

### 検索
ツールバーの **「検索...」** 欄にキーワードを入力すると、名前やタグなどに一致するワークフローだけが表示されます。
入力欄の右端の **×** を押すと、検索文字がすぐに消えます。

### 並べ替え
検索欄の横のプルダウンで、並び順を変えられます。

| 選択肢 | 並び順 |
| --- | --- |
| Date (Newest) | 新しい順 |
| Date (Oldest) | 古い順 |
| Name A-Z | 名前の昇順 |
| Name Z-A | 名前の降順 |

選んだ並び順は記憶され、次に開いたときも同じ順番で表示されます。

### フィルタをまとめて解除
検索・グループ・バッジで絞り込んでいるうちに、「なぜか一覧に出てこない」と迷うことがあります。
そんなときは、ツールバー右端の **「× クリア」** を押してください。
検索文字・グループ・バッジの絞り込みが一度に解除され、すべてのワークフローが表示されます。

## 4-6 インポートとキャンバスへ送る

### ワークフローを取り込む（インポート）
ネットから入手したワークフローのファイル（`.json` または ワークフロー入りの `.png`）は、
次のどちらかの方法でワークフロータブに取り込めます。

- ツールバーの **「インポート」** ボタンを押して、ファイルを選ぶ（複数選択も可能）
- ファイルを、ワークフロータブの一覧部分に **ドラッグ＆ドロップ** する

取り込んだワークフローは、ComfyUIのワークフロー保存フォルダに保存され、一覧に追加されます。

### 選んだワークフローを使う
ワークフローをクリックして選択すると、ツールバーの次の3つのボタンが押せるようになります。

| ボタン | 動き |
| --- | --- |
| 生成UIに読み込み | 生成UIタブに読み込み、ノード画面を触らずに生成できる状態にする（第5章） |
| Videoに読み込み | 動画生成用のワークフローをVideoタブに読み込む（第11章） |
| キャンバスへ送る | ComfyUIのノード画面にワークフローを読み込む |

> **ポイント**
> ボタンが押せない（灰色の）ときは、まだワークフローを選択していません。
> 一覧のワークフローを一度クリックしてから押してください。

**「キャンバスへ送る」** を押すと、Workflow Studioを開いたComfyUIのノード画面に、そのワークフローが読み込まれます。
Workflow Studioで探して、ComfyUIで細かく編集する、という使い方ができます。

> **注意**
> 「キャンバスへ送る」は、ComfyUIの **Wボタンから開いた** Workflow Studioで使えます。
> ブックマークなどから直接開いた場合は、ComfyUI側のWS Libraryにそのワークフローが表示されるので、
> そこからキャンバスへドラッグしてください（第2章・第9章）。

## 4-7 生成UIで動くか事前にチェックする（GenerateUIチェック）

すべてのワークフローが、生成UI（第5章）でそのまま使えるわけではありません。
特殊なカスタムノードを使っていたり、手元にないモデルを指定していたりすると、うまく動かないことがあります。

そこで、生成UIに読み込む前に、使えそうかどうかを自動でチェックする機能があります。

### チェック結果の見方
ワークフローをクリックすると、サイドパネルのワークフロー名の下に、次の情報が表示されます。

- **形式バッジ** － ワークフローの保存形式（UI形式／API形式／App形式）
- **変換** － 生成UIで使える形に変換できるか
- **操作性** － 生成UIの画面だけで、どのくらい設定を変えられるか

それぞれ、次の3段階で表示されます。

| 表示 | 意味 |
| --- | --- |
| ○（チェックマーク） | 問題なし |
| △（警告マーク） | 使えるが注意が必要 |
| ×（バツ印） | 生成UIでは使えない、または使いにくい |

バッジにマウスを重ねると、判定の理由が表示されます。

### よくある判定と対処
| 判定 | よくある理由 | 対処 |
| --- | --- | --- |
| 変換 × | ワークフローに必要なカスタムノードがインストールされていない | ComfyUI Managerで不足しているノードをインストールする（第12章） |
| 変換 △ | 指定されたモデルやLoRAが手元にない | 生成UIで手元のモデルを選び直す。UI形式の場合は、自動で一覧の先頭のモデルに差し替えられるので注意 |
| 操作性 △／× | 生成UIに表示されない設定が多い | 表示されないノードの設定は、ComfyUIのノード画面で変更する |

> **ポイント**
> 操作性は、「設定を持つノードのうち、生成UIに表示されるものの割合」です。
> 80%以上で ○、50%以上で △、それ未満で × になります。
> △ や × でも生成自体はできることが多いので、「生成UIだけで完結しにくい」という目安として見てください。

> **ポイント**
> チェックは、そのワークフローで使っているノードの情報だけをComfyUIから取得して行います（v0.8.8〜）。
> 以前は最初の1回に数十秒かかることがありましたが、今は一瞬で結果が出ます。

## 4-8 付属のサンプルワークフローを使ってみる

Workflow Studioには、すぐに試せるサンプルワークフローが付属しています。
サンプルは、Workflow Studioをインストールしたフォルダの中の **`workflows`** フォルダにあります。

```
ComfyUI/custom_nodes/ComfyUI-Workflow-Studio/workflows/
```

各サンプルには、同じ名前の `.json`（ワークフロー本体）と `.png`（サムネイル画像）が入っています。

### はじめての方におすすめのサンプル
| ファイル名 | 内容 |
| --- | --- |
| `ws_sdxl_t2i_basic` | SDXLモデルで、文章から画像を作る基本のワークフロー |
| `ws_sd15_t2i_basic` | SD1.5モデルで、文章から画像を作る基本のワークフロー |

お手元にあるモデルの種類（SDXLかSD1.5か）に合わせて選んでください。

### サンプルを取り込む
1. ワークフロータブの **「インポート」** を押します。
2. 上記の `workflows` フォルダを開き、使いたいサンプルの `.png` ファイルを選びます。
   （`.png` を選ぶと、サムネイル付きで取り込まれます）
3. 一覧に追加されたことを確認します。

ほかにも、ポーズ指定やインペイント（画像の一部の描き直し）など、応用的なサンプルも入っています。

> **注意**
> 一部のサンプルは、追加のカスタムノードが必要です。
> ノード画面で赤く表示されるノードがある場合は、ComfyUI Managerで不足しているノードをインストールしてください（第12章）。
> 4-7のGenerateUIチェックで「変換 ×」と表示されるのも、多くはこのケースです。

次の章では、取り込んだ基本のサンプルを生成UIに読み込んで、いよいよはじめての1枚を生成します。

> **この章のまとめ**
> - ComfyUIで保存したワークフローは、自動でワークフロータブに並ぶ
> - クリックでサイドパネルに表示、ダブルクリックで詳細画面
> - カメラボタンで、ワークフローに見分けやすいサムネイルを付けられる
> - お気に入り・バッジ・グループで分類し、検索・並べ替えで探す。迷ったら「× クリア」
> - 「生成UIに読み込み」「キャンバスへ送る」で、選んだワークフローをすぐ使える
> - GenerateUIチェックで、生成UIで動くかを事前に確認できる

# 第5章 生成UIタブ － ノードを触らずに画像を作る

いよいよ、Workflow Studioで画像を生成します。
**生成UI（GenerateUI）** タブは、ワークフローの中から「プロンプト」「モデル」「サイズ」など
よく変える項目だけを取り出して、入力フォームとして表示してくれる画面です。
ノードを探して線をたどる必要はありません。

この章の前半（5-1〜5-4）では、第4章で取り込んだ基本のサンプルを使って、はじめての1枚を生成します。

> **事前に準備しておくもの**
> - ComfyUIが起動していること
> - Checkpointモデルが1つ以上、ComfyUIの `models/checkpoints` フォルダに入っていること
> - 第4章で、サンプルワークフロー（`ws_sdxl_t2i_basic` など）を取り込んでいること

---

## 5-1 ワークフローを生成UIに読み込む

1. **ワークフロー** タブを開きます。
2. 使いたいワークフロー（例：`ws_sdxl_t2i_basic`）を **クリック** して選択します。
3. サイドパネルの **GenerateUIチェック**（第4章 4-7）で、「変換」が ○ になっていることを確認します。
4. ツールバーの **「生成UIに読み込み」** を押します。

自動で **生成UI** タブに切り替わり、ワークフローの内容が読み込まれます。
画面上部に、読み込んだワークフローの名前が表示されていれば成功です。

> **ポイント**
> 生成UIの画面は、ボタンや項目名の多くが英語のまま表示されます。
> 本書では、英語の表示名をそのまま使い、必要に応じて意味を添えて説明します。

---

## 5-2 生成UIの画面の見方

生成UIタブは、大きく次の部分に分かれています。

| 番号 | 場所 | 役割 |
| --- | --- | --- |
| ① | 上部のバー | ComfyUIとの接続状態、ワークフロー名、各種ボタン |
| ② | サブタブ | Input／Model／Settings／Feeder／Batch／Lab の切り替え |
| ③ | 編集エリア（中央） | 選んだサブタブの設定項目 |
| ④ | Raw JSON（右側） | ワークフローの中身をJSONで表示（上級者向け） |
| ⑤ | 生成パネル | Generateボタン、進み具合、シード設定、生成結果 |

### ① 上部のバー
| 表示・ボタン | 意味 |
| --- | --- |
| Connected／Disconnected | ComfyUIとつながっているか。緑の **Connected** なら生成できます |
| Connect | ComfyUIに接続し直す |
| Refresh Models | モデルの一覧を読み込み直す（ComfyUIにモデルを追加したあとに押す） |
| Reset Workflow | 編集した内容を捨てて、ワークフローを読み込んだ直後の状態に戻す |
| ワークフロー名 | いま読み込んでいるワークフロー |

> **ポイント**
> 生成UIタブを開くと、ComfyUIへの接続は自動で行われます。
> **Disconnected** と表示されている場合は、ComfyUIが起動しているか確認して **Connect** を押してください。

### ② サブタブ
| サブタブ | 何を設定するか | 本書 |
| --- | --- | --- |
| Input | プロンプト、入力画像 | 5-3 |
| Model | Checkpoint・VAE・LoRAなどのモデル | 5-3 |
| Settings | シード・ステップ数・サンプラー・画像サイズなど | 5-4 |
| Feeder | フォルダの画像を順番に処理する | 5-6 |
| Batch | 条件を変えながらまとめて生成する | 5-5 |
| Lab | 実験的なI2Iバッチ生成（上級） | 5-7 |

まずは **Input・Model・Settings** の3つだけ覚えれば十分です。

### ④ Raw JSON
Input・Model・Settingsの右側には、ワークフローの中身がJSON形式で表示されます。
フォームで値を変えると、ここにも反映されます。
慣れないうちは、ここは「見るだけ」にしておきましょう。

## 5-3 はじめての1枚を生成する

いよいよ生成です。最低限、次の3つを確認・設定します。

1. どのモデルで描くか（Model）
2. 何を描くか（Input → Prompt）
3. 生成する（Generate）

### 手順1：モデルを選ぶ（Model）
1. サブタブの **Model** を開きます。
2. **Checkpoint** の欄で、手元にあるモデルを選びます。
   一覧が長い場合は、欄の上の入力欄に文字を入れると絞り込めます。
3. 欄の下にある **Apply** ボタンを押します。

> **ポイント：モデルが見つからないとき**
> ワークフローに保存されているモデルが、あなたのパソコンに入っていないことがあります。
> 配布されているワークフローを使うときは、ほぼ必ず起こります。次のどちらかの形で知らせてくれます。
> - 欄に「△ （モデル名）（見つかりません）」と表示される
> - 読み込んだときに「このワークフローのCheckpoint「…」が見つからず、無警告で別のモデルに差し替えられました」と表示される
>   （この場合、手元のモデルの一覧の先頭のものに自動で差し替わっています）
>
> なお v0.8.7〜は、フォルダ名が違うだけで同じファイル名のモデルが手元に1つだけあれば、先頭のものではなく、そのモデルに自動で差し替わります。
> （公式テンプレートはフォルダ名なしでモデル名を保存していることが多く、以前は無関係なモデルに差し替わることがありました）
>
> どちらの場合も、一覧から使いたいモデルを選び直して、Apply を押してください。
> 毎回選び直すのが面倒なときは、設定タブの **デフォルトCheckpoint**（第11章）が便利です。

> **注意：Applyを押し忘れない**
> 生成UIでは、モデルやSettings（5-4）の値を変えたあと **Apply** ボタンを押して、はじめてワークフローに反映されます。
> Applyを押さずにGenerateすると、**変更前の値のまま** 生成されてしまいます。
> 「設定を変えたのに結果が変わらない」ときは、まずApplyの押し忘れを疑いましょう。
> （プロンプトの入力欄だけは、Generateを押したときに自動で反映されます）

> **ポイント**
> 項目名が明るい緑色で表示されているのは、読み込んだワークフローにそのモデルのノードが含まれている項目です。
> 緑色でない項目は、変更してもこのワークフローには影響しません。

### 手順2：プロンプトを書く（Input）
1. サブタブの **Input** を開き、その中の **Prompt** を選びます。
2. **Positive Prompt** の欄に、描いてほしい内容を英語で入力します。

   ```
   a cute cat sitting on a windowsill, sunlight, soft colors, high quality
   ```

3. **Positive Prompt** の **Apply** を押します。
4. 必要に応じて **Negative Prompt** の欄に、描いてほしくない内容を入力し、こちらも **Apply** を押します。

> プロンプトは、Applyを押し忘れてもGenerateを押したときに自動で反映されます。
> ただし、Raw JSON（右側）で反映結果を確かめられるので、Applyを押す習慣をつけておくと安心です。

   ```
   low quality, blurry, bad anatomy
   ```

> **ポイント**
> Apply の横にある **↺（戻す）** ボタンを押すと、入力欄の内容を、いまワークフローに反映されている値に戻せます。
> 書き換えに失敗したときに便利です。

> **ポイント**
> 英語が苦手な方は、第7章・第10章で紹介するAI翻訳機能を使うと、日本語で考えたプロンプトを英語にできます。

### 手順3：生成する（Generate）
1. 画面の生成パネルにある **Generate** ボタンを押します。
2. 進み具合を表すバーが伸びていき、パーセントが表示されます。
3. 「Done」と表示されると、生成された画像が生成パネルに表示されます。

おめでとうございます。これで、Workflow Studioではじめての1枚が完成しました。

生成した画像は、ComfyUIで生成した場合と同じく、ComfyUIの `output` フォルダに保存されます。
あとから見返したいときは、**ギャラリー** タブ（第8章）で一覧できます。

> **ポイント：途中で止めたいとき**
> 生成中は、Generateボタンの横に **Stop** ボタンが表示されます。押すと生成を中断します。

> **ポイント：ApplyとGenerateを一度に**
> **Alt キーを押しながら Apply** をクリックすると、値の反映と生成を一度に行えます。
> 慣れてきたら、プロンプトを書き換えて Alt＋Apply、という流れで手早く試せます。

### 生成したワークフローを保存する
生成UIで変えた設定を、あとでまた使いたいときは、サブタブの右端にある **Save** ボタンを押します。
名前を付けて保存すると、ワークフロータブに新しいワークフローとして追加されます。

## 5-4 シード・サンプラー・ステップ数の意味

1枚目が生成できたら、次は **Settings** サブタブで、画像の仕上がりを左右する設定を見てみましょう。

Settingsタブは、左右2つのブロックに分かれています。

- **KSampler（左）** － 画像をどのように描くかの設定
- **Latent Image（右）** － 画像の大きさと枚数の設定

ここでも、値を変えたら各ブロックの **Apply** を押すのを忘れないようにしましょう。

### KSampler の項目
| 項目 | 意味 | 初心者向けの目安 |
| --- | --- | --- |
| Seed（シード） | 画像のもとになる「乱数の種」。同じ設定・同じシードなら、ほぼ同じ画像になる | 生成時は生成パネルのシード設定（下記）が優先されるので、ここは「読み込んだワークフローのシードの確認用」と考える。ワークフローのシードをそのまま使いたいときは、生成パネルのモードを **Workflow** にする |
| Steps（ステップ数） | 描き込みを何回くり返すか。多いほど丁寧だが時間がかかる | 20〜30 |
| CFG | プロンプトにどれだけ忠実に従うか。高すぎると色や形が崩れやすい | SDXLなら5〜8程度 |
| Sampler（サンプラー） | 描き方のアルゴリズム | `euler`、`dpmpp_2m` など |
| Scheduler（スケジューラー） | ステップごとの描き込み量の配分 | `normal`、`karras` など |
| Denoise | 元の画像をどれだけ描き変えるか。文章から作る場合は 1.0 | 1.0（画像から作る場合は 0.4〜0.7 など） |

> **ポイント**
> 目安の値はモデルによって異なります。モデルの配布ページ（Civitaiなど）に推奨値が書かれていることが多いので、確認してみましょう。
> 迷ったら、サンプルワークフローに最初から入っている値のまま使えば大丈夫です。

### Latent Image の項目
| 項目 | 意味 | 目安 |
| --- | --- | --- |
| Width（幅） | 画像の横の大きさ（ピクセル） | SDXLなら1024前後、SD1.5なら512前後 |
| Height（高さ） | 画像の縦の大きさ（ピクセル） | 同上 |
| Batch Size | 1回の生成で何枚作るか | 1〜4（多いほどメモリを使う） |

> **注意**
> モデルが学習したサイズから大きく外れると、人物が二重になったり、構図が崩れたりしやすくなります。
> 縦長・横長にしたいときも、合計のピクセル数がおおよそ同じになるように調整しましょう（例：SDXLなら 832×1216 など）。

### シードの管理（生成パネル）
シードは、生成パネルの **Seed** 欄と、その下のプルダウンで管理します。

| モード | 動き | 使いどころ |
| --- | --- | --- |
| Random | 毎回ランダムなシードで生成 | いろいろな絵を試したいとき |
| Fixed | Seed欄の値で固定 | 気に入った絵をもとに、プロンプトだけ変えて比べたいとき |
| Increment | 生成するたびに1ずつ増やす | 少しずつ違う絵を順番に作りたいとき |
| Decrement | 生成するたびに1ずつ減らす | Incrementの逆 |
| Workflow | ワークフローに入っているシードを、上書きせずそのまま使う | ギャラリーから読み込んだ画像や、配布されたワークフローを、元のシードで再現したいとき |

生成が終わると、Seed欄には **実際に使われたシード値** が表示されます。

> **ポイント：Workflowモード（v0.8.3〜）**
> モードを **Workflow** にすると、Seed欄の値やランダムではなく、読み込んだワークフロー自身のシードで生成します。
> Randomで何枚か試したあとでも、ワークフロー本来のシード（読み込んだ時点の値）に戻って生成されます。
> ワークフローにシードの入力が見つからない場合は、Seed欄の値（−1ならランダム）が使われます。
> 同じシードと同じ設定で続けて2回押すと、ComfyUIは計算済みの結果を再利用するため、新しい画像は増えません（故障ではありません）。

### 気に入った絵を「育てる」流れ
シードを使うと、気に入った1枚をもとに少しずつ改良できます。

1. **Random** で何枚か生成し、気に入った構図の絵を探す
2. 気に入った絵が出たら、モードを **Fixed** に切り替える（Seed欄にはその絵のシードが入っています）
3. プロンプトに言葉を足したり、Stepsを変えたりして、違いを比べる

シードを固定すると、「何を変えたら、どう変わったか」が分かりやすくなります。
これは、画像生成に慣れるためのいちばんの近道です。

> **この章（前半）のまとめ**
> - ワークフロータブで選んで「生成UIに読み込み」を押すと、生成UIで編集できる
> - 基本は Input（プロンプト）・Model（モデル）・Settings（細かい設定）の3つのサブタブ
> - モデルやSettingsの値を変えたら必ず **Apply**。押し忘れると変更前の値で生成される（プロンプトは自動で反映）
> - Generate で生成。Alt＋Apply なら反映と生成を一度に行える
> - シードを Fixed にすると、気に入った絵をもとに条件を変えて比べられる。ワークフローのシードをそのまま使うなら Workflow

## 5-5 バッチ生成 － 条件を変えながらまとめて試す

画像生成に慣れてくると、こんなことを試したくなります。

- 同じプロンプトで、手持ちのモデルを全部試して比べたい
- いくつかのプロンプトを、順番に生成したい
- どのサンプラーがこのモデルに合うのか、まとめて確かめたい

1枚ずつ設定を変えてGenerateを押すのは大変です。
**Batch** サブタブを使うと、「何を変えながら生成するか」をまとめて指定し、自動で順番に生成できます。

### バッチで変えられるもの
バッチでは、次の7種類のうち **1種類** を選んで、順番に変えながら生成します。

| 種類 | 何が変わるか | 使いどころ |
| --- | --- | --- |
| Checkpoint | モデル | モデルの描き味を比べる |
| Lora | LoRA | LoRAの効果を比べる |
| Prompt | プロンプト | 保存したプロンプトを順番に試す |
| Workflow | ワークフロー | 複数のワークフローを順番に実行する |
| Sampler | サンプラー | サンプラーの違いを比べる |
| Scheduler | スケジューラー | スケジューラーの違いを比べる |
| Style | スタイル | スタイルの違いを比べる |

> **ポイント**
> 一度に変えられるのは1種類だけです。
> 「モデルもプロンプトも同時に変えたい」という場合は、5-7の Lab を使います。

### Batchタブの画面
Batchタブは、左・中央・右の3つの部分に分かれています。

| 場所 | 役割 |
| --- | --- |
| 左（リスト） | Checkpoints／Sampler／Scheduler／Style を一覧から選ぶ |
| 中央（グループ） | Checkpoint／Lora／Prompt／Workflow を「グループ」単位で選ぶ |
| 右（Batch Queue） | 選んだ項目の一覧。実行する種類をここで決める |

中央のグループは、それぞれのタブで作ったグループと連動しています。

- Checkpoint・Lora のグループ → モデルタブ（第6章）
- Prompt のグループ → プロンプトタブ（第7章）
- Workflow のグループ → ワークフロータブ（第4章）

### 例：手持ちのモデルを比べる
同じプロンプト・同じシードで、3つのモデルの描き味を比べてみましょう。

1. 5-3の手順で、比べたいプロンプトを入れたワークフローを読み込んでおきます。
2. 生成パネルのシードのモードを **Fixed** にします。
   （シードを固定すると、モデル以外の条件がそろい、違いが分かりやすくなります）
3. **Batch** サブタブを開きます。
4. 左側の **Checkpoints** タブで、比べたいモデルにチェックを入れます。
5. 右側の **Batch Queue** で、**Checkpoint** の列の見出しにあるチェックボックスをオンにします。
   列には、選んだモデルの一覧と件数が表示されます。

6. **Generate** を押します。

選んだモデルで順番に生成が行われます。
生成パネルの **Batch** 欄に、いま何番目を生成しているか、全体の進み具合が表示されます。

- **Pause** － 一時停止します。もう一度押すと再開します。
- **Stop** － バッチ全体を中止します。

> **注意**
> Batch Queueの列のチェックがオンのままだと、次にGenerateを押したときもバッチ生成になります。
> 1枚だけ生成したいときは、列のチェックをオフにしてください。

> **ポイント：LoRAのバッチ**
> Loraのバッチでは、選んだLoRAの書式（`<lora:名前:強さ>`）と、Civitaiから取得したトリガーワードが、
> 自動でPositive Promptに追加されます。バッチが終わると、元のプロンプトに戻ります。

## 5-6 Feeder － フォルダの画像を順番に処理する

**Feeder** は、たくさんの画像を1枚ずつワークフローに送り込んで、順番に処理する機能です。
たとえば、次のような使い方ができます。

- 撮りためた写真を、まとめてイラスト風に変換する（I2I：画像から画像を作る）
- 複数の画像からポーズを読み取って、同じポーズのキャラクターを描く

Feederには2つのモードがあり、Feederタブ左上の **[Image Loop]／[Gallery]** ボタンで切り替えます。

| モード | 画像の取り出し元 | 必要なもの |
| --- | --- | --- |
| Image Loop | パソコン内のフォルダ | カスタムノード **comfyui-image-feeder**（別途インストール） |
| Gallery | ギャラリータブのグループ | 追加インストール不要（Workflow Studioに付属の **Gallery Feeder (WFS)** ノード） |

> **ポイント**
> どちらのモードも、**ワークフローの中に専用のノード** が入っている必要があります。
> 普通のワークフローを読み込んだだけでは使えません。

### Galleryモードの使い方（追加インストール不要）
1. ComfyUIのノード画面で、ワークフローの「画像を読み込む」部分に **Gallery Feeder (WFS)** ノードを置き、
   画像の出力をつなぎます。保存して、生成UIに読み込みます。
2. **ギャラリー** タブ（第8章）で、処理したい画像をグループにまとめておきます。
   （Feederタブを初めて開くと、`__Feeder__` というグループが自動で作られます。これを使ってもかまいません）
3. 生成UIの **Feeder** サブタブを開き、**[Gallery]** を選びます。
4. 対象の **Gallery Feeder Node** と、画像を取り出す **グループ** を選び、**Apply** を押します。
5. 中央にグループの画像が並びます。画像をクリックすると、その画像から処理を始められます。
6. **After gen**（生成後の動き）を選び、**▶ Run** を押します。

### After gen（生成後の動き）
| モード | 動き |
| --- | --- |
| Loop | 次の画像へ進み、最後まで行ったら最初に戻って続ける（■ Stopを押すまで止まらない） |
| Increment | 次の画像へ進み、最後の画像を処理したら自動で止まる |
| Fixed | 同じ画像を使い続ける（シードだけ変えて何枚も作りたいとき） |

はじめは **Increment** を選ぶと、全部の画像を1回ずつ処理して自動で止まるので安心です。

### Image Loopモード
Image Loopモードでは、パソコン内のフォルダ（`ComfyUI/user/default/image-loop-data/`）の画像を使います。
フォルダの画像を選んで、プリセットとして保存しておくこともできます。
別途 **comfyui-image-feeder** カスタムノードが必要です。

付属のサンプル `ws_sdxl_image_feeder_i2i`（I2I）と `ws_dwpose_image_feeder`（ポーズ読み取り）は、このImage Loopモード用です。

### Galleryモードのサンプル（v0.8.3〜）
Galleryモードには、付属のサンプル `ws_sdxl_gallery_feeder_i2i`（SDXLのI2I）が使えます。
ノードを自分で置く必要がなく、**Gallery Feeder (WFS)** ノードがあらかじめ入っています（グループ名は `__Feeder__`、並び順は filename_asc）。

1. ワークフロータブでサンプルを取り込み、**生成UIに読み込み** を押します。
2. ギャラリーで、処理したい画像のサムネイル左上の **F** ボタンを押して `__Feeder__` グループに入れます。
3. **Feeder** サブタブで **[Gallery]** を選び、Gallery Feeder Node とグループを選んで **Apply**。
4. Model サブタブで、手元のCheckpointとVAEを選び直して **Apply**（サンプルのモデル名は作者の環境のものです）。
5. **After gen** を **Increment** にして **▶ Run** を押します。

## 5-7 Lab － 実験的なI2Iバッチ生成（上級）

**Lab** は、5-5のバッチ生成をさらに発展させた、上級者向けの実験的な機能です。
はじめのうちは読み飛ばしてもかまいません。

### Batchとの違い
| | Batch（5-5） | Lab |
| --- | --- | --- |
| 一度に変えられるもの | 1種類だけ | モデル・プロンプト・KSamplerを **それぞれ別々に** |
| 変えるタイミング | 毎回 | 「何回目から変えるか」を自由に指定 |
| 生成した画像を次の入力に | できない | できる（連鎖させられる） |

### キーフレームという考え方
Labでは、「何回目の生成から、どの設定に切り替えるか」を **キーフレーム** として指定します。

例：10回生成する場合

| 回 | モデル | プロンプト | KSampler |
| --- | --- | --- | --- |
| 1〜10 | モデルA | － | － |
| 1〜4 | － | 「朝の街」 | － |
| 5〜10 | － | 「夜の街」 | － |
| 1〜7 | － | － | Steps 20 |
| 8〜10 | － | － | Steps 40 |

このように、列ごとに切り替えのタイミングを別々に決められます。
次のキーフレームが来るまでは、前の設定が引き継がれます。

### 基本の流れ
1. 生成UIにワークフローを読み込みます。
2. **Lab** サブタブを開きます。
3. I2I（画像から画像）の場合は、元になる画像をドロップします。
   文章から作る（T2I）場合は、**T2I workflow (no source image)** にチェックを入れます。
4. 生成回数（Batch）を決めます。
5. Model・Prompt・KSampler の各列で **＋** を押してキーフレームを追加し、
   キーフレームをダブルクリックして、「何回目から」「どの設定に」するかを入力します。
6. **Run** を押します。

結果は **Results** パネルに一覧表示されます。

### 便利な機能
- **Use generated image for next** － 生成した画像を、次の回の入力画像として使います。
  少しずつ変化していく連続画像を作れます。
- **Plan Save** － 設定（プラン）を保存できます。保存すると、結果をまとめた一覧画像も作られ、
  その画像をドロップすれば同じプランを読み込み直せます。

## 5-8 パートナーAPI（Nano Banana）を使う

ComfyUIには、Googleの画像生成モデル **Nano Banana**（Gemini画像ノード）のように、
クラウドのサービスに生成を任せる **パートナーAPIノード** があります。
v0.8.6〜は、こうしたノードを含むワークフローも生成UIで実行できます。

> **注意**
> パートナーAPIノードは、自分のパソコンのGPUではなくクラウドで動き、**Comfyクレジット（有料）を消費** します。
> BatchやLabなどで繰り返し実行すると、回数ぶんのクレジットが続けて消費されます。

### 準備：Comfy APIキーを設定する
1. platform.comfy.org でComfy APIキーを発行します。
2. プラグインのフォルダにある `.env` に、`COMFY_API_KEY=発行したキー` という行を追加します。
   （`.env` がなければ `.env.example` をコピーして作ります）
3. ComfyUIを再起動します。`.env` は起動時にしか読み込まれません。

キーはサーバー側でだけ使われ、ブラウザには送られません。
キーを設定していない状態で実行すると、「パートナーAPIノードの認証に失敗しました」という案内が出ます。

### 使い方
1. ワークフロータブで、Nano Bananaのサンプル（`ws_nano_banana_2_1_t2i`）を生成UIに読み込みます。
2. **Prompt** サブタブでプロンプトを編集し、**Apply** を押します。
3. 参考画像を使うときは、**Image** サブタブの画像カードで指定します。
4. **Generate** を押します。

> **ポイント**
> ComfyUI本体の画面でログインして実行する方法もあります。その場合は `.env` の設定は要りません。

---

## 5-9 対応ワークフローが増えました（v0.8.4〜）

生成UIで使えるワークフローが、次のように増えています。使い方は、ほかのワークフローと同じです。

| 対応したもの | 内容 |
| --- | --- |
| Qwen Image 2.1 Turbo | ComfyUI公式テンプレートの文章から画像（T2I）・画像から画像（I2I）。プロンプトエンハンサー（プロンプトを自動で補う機能）の入力欄にも、編集が反映される |
| Flux.3 Klein | 公式テンプレート4種（KleinとKlein SDのT2IとImage Edit） |
| MOSS-Image | Base／SFTのT2Iと、枠で位置を指定するバウンディングボックス版 |
| ネイティブLoRAスタック | ComfyUI v0.40のLoRAをまとめて読み込むノード（LoadLoraModel／LoadLoraTextEncoder）。Apply・バイパス・Metadata表示に対応 |

> **注意**
> ネイティブLoRAスタックのノードは、保存形式が **API形式のワークフローのみ** 対応です。
> ComfyUI本体の画面がこのノードの行追加にまだ対応していないためで、UI形式のワークフローは対象外です。

> **ポイント**
> 画像のメタデータを見るMetadataタブとサイドパネルの **I** タブでも、Nano Bananaで作った画像を読めます（v0.8.5〜）。
> プロンプトは、Positive／Negativeに分けずに全文が1件で表示されます。

> **この章（後半）のまとめ**
> - Batchサブタブで、モデル・プロンプト・サンプラーなどを1種類ずつ変えながらまとめて生成できる
> - Batch Queueの列のチェックで種類を選び、Generateで開始。終わったらチェックを外す
> - Feederは、たくさんの画像を1枚ずつワークフローに送り込む機能。専用ノードが必要
> - Labは、複数の設定を別々のタイミングで切り替えられる上級者向けの機能
> - パートナーAPIノード（Nano Bananaなど）は、`.env` の `COMFY_API_KEY` を設定すれば実行できる。クレジットが消費される

# 第6章 モデルタブ － モデルとLoRAを管理する

画像生成を続けていると、モデルやLoRAのファイルはどんどん増えていきます。
「このファイル、何のモデルだっけ？」「あのLoRAのトリガーワードは何だった？」
－ そんな悩みを解決するのが **モデル（Models）** タブです。

---

## 6-1 モデルの種類

モデルタブの上部には、モデルの種類ごとのタブが並んでいます。
それぞれ、ComfyUIの `models` フォルダの中の対応するフォルダに入っているファイルが表示されます。

| 種類 | ひとことで言うと | 主な置き場所 |
| --- | --- | --- |
| Checkpoint | 画像生成の本体。これがないと始まらない | `models/checkpoints` |
| LoRA | 絵柄・キャラクター・服装などを追加で覚えさせる小さなモデル | `models/loras` |
| VAE | 画像の色合いや細部を仕上げる。Checkpointに内蔵されていることも多い | `models/vae` |
| ControlNet | ポーズや線画など、構図を指定するためのモデル | `models/controlnet` |
| UNET | FLUXなど新しい形式のモデルの本体（Diffusion Model） | `models/diffusion_models` など |
| TextEncoder | プロンプトの文章をAIが理解できる形に変換するモデル | `models/text_encoders` など |
| Hypernetwork | 絵柄を調整する古い形式の追加モデル | `models/hypernetworks` |
| Embedding | 特定の単語に意味を覚えさせた小さなファイル（ネガティブ用が多い） | `models/embeddings` |

> **ポイント**
> はじめは **Checkpoint** と **LoRA** の2つを使いこなせれば十分です。
> FLUXなどの新しいモデルを使うようになると、UNETやTextEncoderの出番が増えてきます。

---

## 6-2 一覧の表示と探し方

### 最初の読み込み
モデルタブを初めて開いたときは、一覧が空で「更新ボタンでモデルを読み込み...」と表示されます。
ツールバーの **「更新」** を押すと、モデルの一覧が表示されます。
新しくモデルを追加したときも、「更新」を押してください。

### サムネイル表示とテーブル表示
ワークフロータブと同じく、**サムネイル** と **テーブル** を切り替えられます。
1ページに24件ずつ表示されます。

テーブル表示では、列の見出しをクリックすると、その列で並べ替えができます
（1回目：昇順 ▲、2回目：降順 ▼、3回目：並べ替え解除）。

> **ポイント**
> サムネイルは、モデルファイルと同じ場所にある `（モデル名）.preview.png` が自動で使われます。
> 画像がないモデルも、6-3の方法でCivitaiから取得したり、自分で設定したりできます。

### 検索と絞り込み
ツールバーには、絞り込みのための項目が並んでいます。

| 項目 | 絞り込み内容 |
| --- | --- |
| モデルを検索... | 名前などのキーワード |
| ★ | お気に入りだけ |
| すべてのタグ | タグ |
| All Folders | サブフォルダ |
| All Groups | グループ |
| All／Enabled only／Disabled only | 有効・無効の状態（6-5） |

絞り込みすぎて分からなくなったら、ツールバー右端の **「× クリア」** ですべて解除できます。

### お気に入り・バッジ・グループ
分類のしかたは、ワークフロータブ（第4章 4-4）とほぼ同じです。

- **お気に入り（★）** － よく使うモデルに印を付ける
- **バッジ** － **「Badge」** で作った色付きラベルを付ける。バッジの種類と色はワークフロータブと共通です
- **グループ** － モデルをクリックし、サイドパネルの **「グループ」** タブで追加する

> **ポイント**
> グループは **モデルの種類ごと** に分かれています。
> Checkpointのグループは、Checkpointタブにだけ表示されます。
> ここで作ったグループは、生成UIのバッチ生成（第5章 5-5）でも使えます。

---

## 6-3 Civitaiの情報を取り込む

**Civitai（シビタイ）** は、画像生成モデルが多数公開されている共有サイトです。
ネットから入手したモデルの多くは、Civitaiで配布されています。

Workflow Studioは、手元のモデルファイルから **ハッシュ値**（ファイルの指紋のような値）を計算し、
Civitaiに登録されている情報を自動で探し出せます。

### 取得できる情報
- モデルの名前・種類（Checkpoint／LoRAなど）
- **Base Model**（SDXL、SD1.5、FLUX など、どの系統のモデルか）
- **トリガーワード**（LoRAの効果を出すために、プロンプトに入れる言葉）
- タグ・説明文
- サンプル画像（サムネイルにも使われます）

### 1つずつ取得する
1. モデルをクリックして選択します。
2. 右側のサイドパネルで **「CivitAI」** タブを開きます（モデルを選ぶと最初にこのタブが開きます）。
3. **「CivitAIから取得」** を押します。

取得が終わると、モデルの情報が表示されます。
**Sample** タブでは、Civitaiに投稿されたサンプル画像を見られます。

### まとめて取得する
ツールバーの **「CivitAI」** ボタンを押すと、表示中の種類のモデルについて、まとめて情報を取得します。
すでに情報を取得済みのモデルは飛ばされるので、モデルを追加したあとに何度押しても大丈夫です。
サムネイル画像がないモデルには、プレビュー画像も自動で保存されます。

> **ポイント**
> ハッシュ値の計算には、モデルの大きさに応じて時間がかかります。
> 数GBのモデルがたくさんある場合は、時間に余裕があるときに実行しましょう。

> **ポイント**
> Civitaiで見つからなかったモデルは「確認済みですが、このモデルはCivitAIに見つかりませんでした。」と表示されます。
> 自分で作ったモデルや、Civitai以外で配布されているモデルは、見つからないのが普通です。
> **「未登録はスキップ」** にチェックを入れておくと、まとめて取得するときに、見つからなかったモデルを再確認せずに飛ばします。

> **ポイント：APIキー**
> 設定タブの **「CivitAI APIキー」** は、入力しなくても使えます（省略可）。
> 一部の情報の取得に認証が必要な場合に、Civitaiのアカウント設定で発行したキーを入力します。

### LoRAを使うときに特に便利
LoRAは、**トリガーワード** をプロンプトに入れないと効果が出ないものが多くあります。
Civitaiの情報を取得しておけば、サイドパネルでトリガーワードをすぐに確認できます。
また、生成UIのバッチ生成でLoRAを使うと、トリガーワードが自動でプロンプトに追加されます（第5章 5-5）。

---

## 6-4 モデルを生成やキャンバスで使う

### 生成UIにセットする（GenUI Model）
モデルタブで選んだモデルを、そのまま生成UIのワークフローにセットできます。

1. 生成UIに、ワークフローを読み込んでおきます（第5章 5-1）。
2. モデルタブで、使いたいモデルを選択します。
3. **「GenUI Model」** ボタンを押します。

これで、生成UIのワークフローのモデルが、選んだモデルに差し替わります。
Civitaiのサンプル画像を見比べながら、気になったモデルをすぐ試せます。

> **ポイント**
> Embeddingの場合は、**GenUI PP**（ポジティブプロンプトに追加）と **GenUI NP**（ネガティブプロンプトに追加）のボタンが表示されます。
> ネガティブ用のEmbeddingは、GenUI NP で追加しましょう。

> **注意**
> 生成UIのワークフローに、そのモデルを読み込むノードがない場合は使えません。
> たとえば、LoRAのノードがないワークフローに、LoRAはセットできません。

### ComfyUIのノード画面で使う
ComfyUIのノード画面の横にある **WS Library** の **M（Models）** タブからモデルをキャンバスへドラッグすると、
そのモデルを読み込むノードが自動で置かれます（第9章）。

---

## 6-5 使わないモデルを片付ける

### 有効・無効の切り替え
しばらく使わないモデルは、削除せずに **無効（Disable）** にしておけます。
無効にしたモデルは、ComfyUIのモデル選択の一覧に表示されなくなるので、一覧がすっきりします。

- カードの **一時停止（⏸）** ボタンで、1つずつ有効・無効を切り替えられます。
- グループ単位で、まとめて有効・無効にすることもできます。

> **ポイント**
> 無効にすると、ファイルの名前の末尾に `.disabled` が付きます。ファイル自体は消えません。
> 有効に戻すと、元の名前に戻ります。

### まとめて操作する（Select）
緑色の **Select** ボタンを押すと、複数のモデルにチェックを入れて、まとめて操作できます。

- グループへの追加・削除
- バッジの追加・削除
- 別のサブフォルダへの移動（プレビュー画像などの関連ファイルも一緒に移動）
- 削除

### 削除
詳細画面やSelectから、モデルを削除できます。

> **注意**
> 削除すると、モデルファイルと、関連するファイル（プレビュー画像、Civitai情報など）が **完全に削除** されます。
> モデルは再ダウンロードに時間がかかるものが多いので、迷ったら削除ではなく「無効」にしておきましょう。

> **この章のまとめ**
> - モデルタブでは、ComfyUIのモデルを種類ごとに一覧できる。最初に「更新」を押す
> - お気に入り・バッジ・グループで分類できる。グループはバッチ生成でも使える
> - 「CivitAIから取得」で、Base Model・トリガーワード・サンプル画像などを自動で取り込める
> - 「GenUI Model」で、選んだモデルをすぐ生成UIで試せる
> - 使わないモデルは削除せず「無効」にしておくと安心

# 第7章 プロンプトタブ － 呪文を貯めて、育てる

うまくいったプロンプトは、あなただけの財産です。
でも、メモ帳に貼り付けておくだけでは、どれが何の呪文だったか分からなくなりがちです。

**プロンプト（Prompt）** タブは、プロンプトを **保存・分類・再利用** するための場所です。
さらに、ローカルAIを使った翻訳や、プロンプトを毎回少しずつ変える「ワイルドカード」も使えます。

---

## 7-1 プロンプトの基本

プロンプトタブの使い方に入る前に、プロンプトの書き方の基本を押さえておきましょう。

### ポジティブとネガティブ
| 種類 | 書く内容 | 例 |
| --- | --- | --- |
| Positive Prompt（ポジティブ） | 描いてほしいもの | `1girl, smiling, school uniform, cherry blossoms, spring` |
| Negative Prompt（ネガティブ） | 描いてほしくないもの | `low quality, blurry, extra fingers, watermark` |

### 書き方のコツ
- **英語で書く** － 多くのモデルは英語で学習されています。
- **カンマ（,）で区切る** － 単語や短いフレーズを、カンマで区切って並べるのが一般的です。
- **大事なものを前に** － 前に書いた言葉ほど、強く反映されやすい傾向があります。
- **強調したい言葉は (言葉:数値)** － `(red hair:1.3)` のように書くと、その言葉を強調できます（1.0が標準）。

> **ポイント：強調の数値をキーボードで変える**
> 生成UIのプロンプト入力欄で、強調したい言葉を選んで **Ctrl＋↑／↓** を押すと、
> `(言葉:数値)` の数値を0.05ずつ増減できます。数値が1.0に戻ると、カッコは自動で外れます。

> **ポイント**
> SDXLのアニメ系モデルは「タグを並べる」書き方、FLUXなどの新しいモデルは「普通の英文で説明する」書き方が向いています。
> モデルの配布ページに、おすすめの書き方が載っていることも多いので確認してみましょう。

---

## 7-2 プロンプトタブの画面

プロンプトタブは、左・中央・右の3つの列に分かれています。

| 列 | 名前 | 役割 |
| --- | --- | --- |
| 左 | AI Assistant | ローカルAIとのチャット・翻訳（7-5） |
| 中央 | Presets／Preset Manager | プロンプトの保存・一覧・分類（7-3） |
| 右 | Wildcard／Style | ワイルドカードとスタイルの管理（7-4） |

画面上部の **Form／Table** で、表示方法を切り替えられます。

- **Form** － 1件ずつ編集する画面（この章で説明する画面です）
- **Table** － プリセットやワイルドカードを表形式でまとめて編集する画面（件数が増えてきたら便利）

---

## 7-3 プリセットとして保存・分類する

**プリセット** は、ポジティブ・ネガティブのプロンプトをひと組にして、名前を付けて保存したものです。

### プリセットを保存する
1. 中央の列で **Presets** タブを開きます。
2. 一番上のプルダウンが **New Preset (none selected)** になっていることを確認します。
3. 次の項目を入力します。

   | 項目 | 内容 |
   | --- | --- |
   | Preset Name | プリセットの名前（例：`桜と制服`） |
   | Category | 分類（例：`Portrait`、`Landscape`）。省略してもかまいません |
   | Positive Prompt | 描いてほしいもの |
   | Negative Prompt | 描いてほしくないもの |

4. **Save** を押します。「プリセットを保存しました」と表示されれば完了です。

> **ポイント**
> 生成UIで試して「これは良い！」と思ったプロンプトを、その場でプリセットに保存する習慣をつけましょう。
> あとから同じ雰囲気の画像を作りたいときに、すぐに呼び出せます。

### プリセットを呼び出して使う
1. 一番上のプルダウンから、使いたいプリセットを選びます。
2. 使い方に応じてボタンを押します。

| ボタン | 動き |
| --- | --- |
| GenUI Set | 生成UIのプロンプト欄に、ポジティブとネガティブをまとめてセットする |
| PP Copy | ポジティブプロンプトをコピーする |
| NP Copy | ネガティブプロンプトをコピーする |

> **注意**
> **GenUI Set** は、生成UIにワークフローが読み込まれているときに使えます。
> 先に第5章の手順でワークフローを読み込んでおきましょう。

### グループで分類する
プリセットも、グループで分類できます。

1. プリセットを選んだ状態で、**+ Group** を押して新しいグループを作ります。
2. **Select group...** からグループを選び、**Add to Group** を押します。

グループは削除することもできます（**Del Group**）。

ここで作ったグループは、生成UIのバッチ生成（第5章 5-5）で「Prompt」のグループとして使えます。
たとえば「季節シリーズ」というグループに春・夏・秋・冬のプリセットを入れておけば、
4つの季節の絵をまとめて生成できます。

### Preset Manager で一覧する
中央の列の **Preset Manager** タブでは、保存したプリセットを一覧で見られます。

- **All** － すべてのプリセット
- **★** － お気に入りに登録したプリセット
- **Groups** － グループごとの表示

上部の **Search presets...** 欄で、プリセットを検索できます。

保存したプリセットは、ComfyUIのノード画面の横にある **WS Library** の **P（Prompts）** タブにも表示され、
キャンバスへドラッグして使えます（第9章）。

---

## 7-4 ワイルドカードとスタイル

右の列では、プロンプトを自動で変化させる **ワイルドカード** と、
プロンプトに雰囲気を足す **スタイル** を管理します。
列の上部の **Wildcard／Style** で切り替えます。

### ワイルドカードとは
ワイルドカードは、**生成するたびに、プロンプトの一部をランダムに入れ替える** しくみです。
同じプロンプトのまま、バリエーションのある画像をたくさん作れます。

Workflow Studioでいちばん手軽なのは、**ワイルドカードファイル** を使う方法です。
候補を書いたファイルを作っておき、プロンプトに `__ファイル名__` と書くと、
生成するたびにファイルの中から1行がランダムに選ばれます。

### ワイルドカードファイルを作る
例として、色の候補を入れた `colors` というファイルを作ってみましょう。

1. 右の列で **Wildcard** を選び、**Wildcard Files** の **+ New** を押します。
2. ファイル名（例：`colors`）を入力し、形式は **txt** を選びます。
3. 候補を1行に1つずつ入力します。

   ```
   red
   blue
   green
   golden
   ```

4. **Save** を押します。

### ワイルドカードを使う
プロンプトに、ファイル名を `__`（アンダースコア2つ）で囲んで書きます。

```
1girl, __colors__ dress, standing in a garden
```

生成UIで生成するたびに、`__colors__` の部分が `red`・`blue`・`green`・`golden` のどれかに置き換わります。

> **ポイント**
> `__colors__` を手で入力する代わりに、右の列の **File** ボタンでファイルを選んで挿入することもできます。

### もっと高度な書き方（Impact Pack 用）
右の列の上部には、`{ }`、`$$`、`[ ]` などの記号を挿入するボタンもあります。
これらは、次のような書き方のためのものです。

| 書き方 | 意味 |
| --- | --- |
| `{cat｜dog｜rabbit}` | 3つの中から1つを選ぶ |
| `{2$$cat｜dog｜bird}` | 3つの中から2つを選ぶ |

※ 本書では見やすさのため `｜` と全角で表記しています。実際には半角の `|`（縦棒）を使います。

> **注意**
> 生成UIが自動で展開するのは、`__ファイル名__` の書き方だけです。
> `{A|B}` などの書き方を使うには、カスタムノード **ComfyUI-Impact-Pack** のワイルドカード用ノード
> （ImpactWildcardProcessor など）をワークフローに入れておく必要があります。
> 慣れないうちは、`__ファイル名__` の書き方だけ使えば十分です。

### 作ったプロンプトを送る
右の列で組み立てたプロンプトは、下のボタンで送り出せます。

- **→ Pos** － プリセットのPositive Promptへ送る
- **→ Neg** － プリセットのNegative Promptへ送る
- **Copy** － コピーする

`__ファイル名__` の部分は、生成UIで生成するときに自動で展開されます。

### スタイル
**スタイル** は、プロンプトに付け足す「雰囲気のテンプレート」です。
たとえば「映画風」というスタイルには、`cinematic still, {prompt}, dramatic lighting` のような内容が登録されています。
`{prompt}` の部分に、あなたのプロンプトが入ります。

スタイルを使うには、生成UIの上部のバーで、**Style** のチェックボックスをオンにして、プルダウンからスタイルを選びます。
生成するときに、選んだスタイルがプロンプトに自動で合成されます（ワークフローそのものは書き換わりません）。

Workflow Studioにはたくさんのスタイルが付属しています。
プロンプトタブの **Style** では、スタイルの一覧を見たり、**+ New** で自分のスタイルを作ったりできます。

> **ポイント**
> どのスタイルがどんな雰囲気になるかは、生成UIの **Create Catalog** で、スタイルごとの見本画像をまとめて作ると分かりやすくなります。
> 作った見本は、ギャラリータブの Style_Catalog で一覧できます（第8章）。

## 7-5 AIで翻訳・プロンプト作りを手伝ってもらう

左の列の **AI Assistant** では、パソコンで動くAI（ローカルAI）に、プロンプト作りを手伝ってもらえます。

> **事前に必要なもの**
> この機能を使うには、**Ollama** や **LM Studio** などのローカルAIソフトと、AIモデルの準備が必要です。
> 準備の方法は第10章で説明します。準備ができていない場合、AI Assistantの上部に **Disconnected** と表示されます。

### 日本語を英語に翻訳する
英語のプロンプトが苦手でも大丈夫です。

1. 左の列の下にある入力欄に、日本語で描きたい内容を書きます。

   ```
   桜の木の下で微笑む制服姿の少女、春の柔らかい光
   ```

2. **Translate:** の **JA→EN** ボタンを押します。
3. チャット欄に、英語に翻訳された結果が表示されます。

翻訳結果の下に表示されるボタンで、結果を使えます。

| ボタン | 動き |
| --- | --- |
| 生成UIに適用 | 生成UIのポジティブプロンプト欄に入れる |
| コピー | コピーする（プリセットに貼り付けるときなど） |

英語のプロンプトの意味を知りたいときは、反対に **EN→JA** で日本語に訳せます。

### AIと相談しながらプロンプトを作る
入力欄に質問を書いて **Send**（または Enter キー）を押すと、AIとチャットできます。

- 「夕暮れの海辺の風景のプロンプトを、英語のタグ形式で作って」
- 「このプロンプトに、もっと幻想的な雰囲気を足して」

のように頼むと、プロンプトの案を出してくれます。
画像を読み取れるAIモデルを使っている場合は、**Attach Image** で画像を添付して、
「この画像の雰囲気をプロンプトにして」と頼むこともできます。

- **Shift＋Enter** － 改行
- **Clear Chat** － 会話をリセット
- **歯車ボタン** － 使うAIソフトやモデルの設定（第10章）

> **注意**
> ローカルAIの答えは、いつも正しいとは限りません。
> 出てきたプロンプトは、実際に生成して確かめながら調整しましょう。

> **この章のまとめ**
> - プロンプトは英語・カンマ区切りが基本。強調は `(言葉:数値)`
> - うまくいったプロンプトは、プリセットとして名前を付けて保存する
> - 「GenUI Set」で、プリセットをすぐ生成UIにセットできる
> - グループに分けると、バッチ生成でまとめて試せる
> - ワイルドカードファイルを作って `__ファイル名__` と書くと、生成のたびにプロンプトを変化させられる
> - ローカルAIを用意すれば、日本語からの翻訳やプロンプトの相談ができる

# 第8章 ギャラリータブ － 生成した画像を見返す

画像生成を続けていると、ComfyUIの `output` フォルダには何百、何千枚もの画像がたまっていきます。
**ギャラリー（Gallery）** タブは、それらの画像を快適に見返し、
「この画像、どうやって作ったんだっけ？」を解決するための場所です。

ComfyUIで生成した画像には、生成に使ったワークフローやプロンプトの情報（**メタデータ**）が埋め込まれています。
ギャラリータブでは、この情報を読み取って、同じ設定をすぐに再現できます。
また、動画（MP4・WebM）や音声ファイル（WAV・MP3・OGG・M4A・FLAC・Opus）も、画像と同じ一覧で扱えます。

---

## 8-1 画像を一覧する

ギャラリータブの上部には、4つのサブタブがあります。

| サブタブ | 役割 | 本書 |
| --- | --- | --- |
| Output | 生成した画像の一覧（ふだん使うのはここ） | 8-1〜8-3 |
| ImagePrompt | 見本画像を見ながらプロンプトを組み立てる | 8-4 |
| Style_Catalog | スタイルの見本画像から選ぶ | 8-4 |
| メタデータ | 画像ファイルをドロップして、中の情報を調べる | 8-2 |

### Outputの画面
**Output** サブタブは、左・中央・右の3つの部分に分かれています。

| 場所 | 役割 |
| --- | --- |
| 左（フォルダ） | `output` フォルダの中のフォルダ一覧。いちばん上の **[root]** が `output` フォルダ全体 |
| 中央（一覧） | 選んだフォルダの画像。下へスクロールすると続きが読み込まれる |
| 右（詳細パネル） | 選んだ画像の情報（8-2） |

まず、左のフォルダ一覧からフォルダを選ぶと、中央に画像が表示されます。

> **ポイント**
> 生成UIやComfyUIで新しく生成した画像が出てこないときは、ツールバーの **Refresh** を押してください。

> **ポイント**
> 読み込む `output` フォルダの場所は、設定タブの **「ギャラリー Outputフォルダ」** で変更できます。

### 表示の切り替え・検索・並べ替え
ほかのタブと同じく、次の操作ができます。

- **サムネイル／テーブル** － サムネイル表示とテーブル表示の切り替え
- **検索欄** － ファイル名・タグ・メモ・**プロンプトの内容** で検索。横の **S** ボタンをオンにすると、文章の意味で探せます（8-6）
- **並べ替え** － Date (Newest)／Date (Oldest)／Name A-Z／Name Z-A
- **★** － お気に入りだけ表示
- **× クリア** － 絞り込みをまとめて解除

> **ポイント**
> 検索欄では、プロンプトの言葉でも探せます。
> たとえば「cat」で検索すると、プロンプトに cat を含む画像が見つかります。
> （プロンプトの検索は、一度詳細パネルで開いた画像が対象になります）

### 大きく見る・比べる
- 画像をクリックすると、右の詳細パネルに大きく表示されます。
- **Ctrl キーを押しながら** 画像をクリックすると、複数の画像を選べます。
  2〜4枚選んで **比較** を押すと、並べて見比べられます。

シードやモデルだけを変えて作った画像を並べると、違いがよく分かります。

### 整理する
- **お気に入り（★）・タグ・メモ・グループ** で分類できます（詳細パネルで設定）。
- 複数選択して、まとめてグループに追加したり、別のフォルダへ移動したりできます。
  移動先を選ぶ画面（**移動先...**）には絞り込み欄があり、フォルダ名の一部を入れると候補が絞られ、Enterで先頭の候補へ移動できます。
- **エクスポート** を押すと、選んだ画像をZIPファイルにまとめてダウンロードできます。

> **注意**
> 詳細パネルの **Delete** や、複数選択の **ファイル削除** を使うと、画像ファイルそのものが削除されます。

## 8-2 メタデータから生成設定を読み取る

画像をクリックすると、右の詳細パネルに4つのタブが表示されます。

| タブ | 内容 |
| --- | --- |
| プロンプト | 画像の生成に使われたプロンプト（最初に表示されるタブ） |
| 基本情報 | ファイル名・大きさ・日時・タグ・メモ |
| メタデータ | 画像に埋め込まれたワークフロー（JSON） |
| グループ | グループの設定 |

### プロンプトを確認する
**プロンプト** タブには、画像に埋め込まれていたプロンプトが一覧表示されます。
ポジティブには **POS**、ネガティブには **NEG** の印が付きます。
項目をクリックすると、全文が表示されます。

### もっと詳しく調べる（メタデータサブタブ）
使ったモデルやLoRAまで詳しく知りたいときは、詳細パネルの **Metadata** ボタンを押します
（または、Alt キーを押しながら画像をクリック）。
ギャラリーの **メタデータ** サブタブが開き、次の情報が整理されて表示されます。

- **モデル** － Checkpoint、VAE、Diffusion Model、Text Encoder（中央の列）
- **LoRA** － 使われたLoRAと、その強さ（中央の列）
- **プロンプト** － ポジティブ・ネガティブ（中央の列）
- **Settings** － 画像サイズ（幅×高さ）と、KSamplerの Seed・Steps・CFG・Sampler・Scheduler・Denoise（右の列。v0.7.14〜）
- **Nanobanana** － Comic Creatorのnanobananaタブで作った画像の、エンジン・モデル・プロンプトなどの生成履歴（右の列。該当する画像のみ）

プロンプトの横のボタンで、内容をほかのタブに送れます。

| ボタン | 動き |
| --- | --- |
| Copy | コピー |
| GenUI:P／GenUI:N | 生成UIのポジティブ／ネガティブに入れる |
| Prompt:P／Prompt:N | プロンプトタブのプリセットのポジティブ／ネガティブに入れる |

> **ポイント：ネットで見つけた画像も調べられる**
> メタデータサブタブの左側に、画像ファイルを **ドロップ** すると、その画像の情報を調べられます。
> ComfyUIの画像だけでなく、SD WebUI（AUTOMATIC1111）、SD Forge、Fooocus で作られたPNG画像にも対応しています。
> 配布サイトで見つけた画像の作り方を知りたいときに便利です
> （ただし、投稿時にメタデータが消されている画像からは読み取れません）。

## 8-3 同じ設定を再現する

ギャラリーのいちばん便利な使い方は、**気に入った画像と同じ設定で、もう一度生成する** ことです。
方法は2つあります。

### 方法1：生成UIで再現する（GenUI）
1. ギャラリーで、再現したい画像をクリックします。
2. 詳細パネルの **GenUI** ボタンを押します。
3. 画像に埋め込まれていたワークフローが、生成UIに読み込まれます。

あとは第5章と同じように、プロンプトを少し変えたり、シードを変えたりして生成できます。

> **ポイント**
> **同じ画像をもう一度作りたいとき（v0.8.3〜）**
> 画像に埋め込まれているワークフローには、そのときのシード値も入っています。
> 生成パネルのシードのモードを **Workflow** にして Generate を押すと、そのシードのまま生成されます。
>
> モードが Random のままだと、別のシードで生成されます。
> また、Fixed を使う場合は、**Settings** サブタブの **Seed** 欄の値を生成パネルの **Seed** 欄に貼り付けてください（生成パネルの値が優先されるため）。

### 方法2：ComfyUIのノード画面で再現する（コピー＆キャンバスへ送る）
1. ギャラリーで、再現したい画像をクリックします。
2. 詳細パネルの **JSON** タブを開きます。
3. **Copy & Send Canvas**（コピー＆キャンバスへ送る）を押します。
   （このボタンは英語表示のままです。ワークフローが埋め込まれた画像でだけ押せます）

ComfyUIのノード画面に、その画像を作ったワークフローが読み込まれます。
ノード画面で細かく手を加えたいときは、こちらを使います。

> **注意**
> 「この画像にはComfyUIワークフローが埋め込まれていません」と表示される場合は、再現できません。
> ワークフローの情報が保存されない設定で作った画像や、別のソフトで編集・圧縮した画像などが当てはまります。

### 画像を次の生成の材料にする
ギャラリーの画像を、生成の「入力画像」として使うこともできます。

| ボタン | 動き |
| --- | --- |
| Send GenUI Image | 選んだ画像を、生成UIのワークフローの入力画像（LoadImageノード）にセットする |
| Send to LI node | 選んだ画像を、ComfyUIのノード画面で選んでいる画像読み込みノードにセットする |
| Image Edit | 選んだ画像を Image Edit タブで開く（第11章） |
| Send CC | 選んだ画像を Comic Creator のコマに送る（Comic Creatorの中でギャラリーを開いたときだけ表示。第11章 11-6） |

I2I（画像から画像を作る）ワークフローで、生成した画像をさらに描き直していくときに便利です。

## 8-4 ImagePrompt と Style_Catalog

### ImagePrompt － 見本画像からプロンプトを組み立てる
**ImagePrompt** は、「見本画像」と「プロンプト」をセットで並べて、
見た目で選びながらプロンプトを組み立てるためのサブタブです。

1. 見本画像をクリックすると、右側にその画像のプロンプトが表示されます。
2. **+ Add** を押すと、**Selected Prompts** に追加されます。
3. いくつか追加すると、**Final Prompt** に、カンマ区切りでまとめたプロンプトができあがります。
4. **Copy** でコピーして、生成UIやプリセットに貼り付けます。

見本画像は、`output` フォルダの中に自動で作られる `ws_image_prompt` フォルダに置きます。
画像と同じ名前の `.txt` ファイル（中身がプロンプト）を一緒に置くと、見本として使えるようになります。

> **例**
> `ws_image_prompt/髪型/ponytail.png` と `ws_image_prompt/髪型/ponytail.txt`（中身：`ponytail, long hair`）

### Style_Catalog － スタイルを見本画像で選ぶ
第7章で紹介したスタイルは、名前だけではどんな雰囲気になるか分かりにくいものです。
**Style_Catalog** では、スタイルごとの見本画像を並べて、見た目で選べます。

見本画像は、生成UIの上部のバーにある **Create Catalog** で作ります。

1. 生成UIに、文章から画像を作るワークフローを読み込みます。
2. **Batch** サブタブの **Style** で、見本を作りたいスタイルにチェックを入れます。
3. 上部のバーの **Create Catalog** を押し、保存先のフォルダを決めて実行します。
4. 上部のバーの **Catalog** を押すと、ギャラリーの Style_Catalog に移動します。

Style_Catalog で見本画像を選び、**Select as Style** を押すと、
生成UIのスタイルが、そのスタイルに切り替わります。

> **ポイント**
> モデルによってスタイルの効き方は変わります。
> 保存先のフォルダをモデルごとに分けておくと、比べやすくなります。

## 8-6 画像を「意味」で探す（セマンティック検索）

通常の検索は、ファイル名・タグ・プロンプトの文字が一致した画像を探します。
**セマンティック検索**（v0.8.2〜）は、画像の「意味」で探します。
たとえば「夕暮れの街並み」と入れると、プロンプトにその言葉が無くても、雰囲気の合う画像が見つかります。
また、選んだ画像に **似た画像** の一覧を出すこともできます。

### 使い方
1. 検索欄の横の **S** ボタンをオンにします。検索欄が意味検索に切り替わり、ツールバーに2行目が現れます。
2. 2行目の **歯車ボタン**（設定）を押し、**インデックス**（検索用の索引）を作ります（下記）。
3. 検索欄に文章を入れて **Enter** を押します。結果はスコア順に並び、サムネイルにスコアが表示されます。
4. 画像を選んで2行目の **Similar** を押すと、その画像に似た画像が並びます。別の画像を選んで **↻（更新）** を押すと、その画像の類似を出し直します。もう一度 **Similar** を押すと、通常の表示に戻ります。

> **ポイント**
> 意味検索の結果には、並べ替えやタグ・グループの絞り込みは効きません。
> 検索の範囲は、選んでいるフォルダの中（サブフォルダを含む）です。
> フォルダツリーの枚数の横に緑の点があるフォルダは、直下の画像がすべてインデックス済みです。

### モデルを選ぶ（歯車ボタンの「モデル設定」タブ）
| モデル | 特徴 | 準備 |
| --- | --- | --- |
| Gemini Embedding 2 | Googleのサービスで計算する。速い。画像をGoogleに送る | APIキーを取得し、プラグインの `.env` に `GEMINI_API_KEY=キー` と書いて、ComfyUIを再起動する |
| EmbeddingGemma 2 | パソコンの中で計算する（ローカル）。外部に送らない | 追加の準備は不要。初回だけモデルが自動でダウンロードされる |

> **注意：Geminiを使うとき**
> 画像がGoogleのサービスに送られます。無料枠で送った内容は、Googleの製品改善に使われる場合があります。
> 公開したくない画像が多い場合は、ローカルの EmbeddingGemma 2 を選んでください。
> APIキーは `.env` にだけ書き、他人に見せないようにしましょう。

### インデックスを作る（歯車ボタンの「インデックス」タブ）
1. 対象のフォルダを選びます（サブフォルダを含めるかも選べます）。
2. 「新規のみ」か「全件再作成」を選んで開始します。進み具合が表示され、途中で停止もできます。
3. インデックスは全フォルダで共通の1つです。フォルダごとに少しずつ作っても構いません。

モデルやベクトル次元、画像の精度を変えたときは、**全件再作成** が必要です。

### 速さの目安と設定
- ローカルのEmbeddingGemma 2は、初期設定ではCPUで動き、1枚あたり数秒かかります。
  **画像の精度** を「標準」や「軽量」にすると速くなります（変えたら全件再作成）。
  **CPUスレッド数** を減らすと、画像生成中のパソコンの負荷が軽くなります。
- NVIDIAのGPUがあれば、ComfyUIのPythonに `onnxruntime-gpu` を入れると、1枚あたり約0.1秒になります（対処は第12章 12-5）。
- **検索設定** タブで、類似画像・文章検索それぞれの「最小スコア」と最大表示件数を決められます。
  スコアの水準はモデルによって違うため、モデルごとに保存されます。

## 8-7 音声ファイルの扱いと変換

ComfyUIで音楽や効果音を作る機会が増えたため、ギャラリーは音声ファイルも扱えます（v0.8.0〜）。
対応しているのは、WAV・MP3・OGG・M4A・FLAC・Opus です。

- 一覧には、音の形（波形）のサムネイルと、♪ のバッジが表示されます。波形の色は形式ごとに違います（MP3は青、WAVは緑、FLACは琥珀色、OGG／Opusは紫、M4Aはピンク）。
- 選ぶと、右の詳細パネルに波形とプレイヤーが表示され、その場で再生できます。
- 保存時にワークフロー（`prompt`／`workflow`）が埋め込まれている音声は、プロンプトやJSONのタブも使えます。
- 動画（MP4・WebM）も同様に一覧できます。**Send to LV node** ボタンで、選んだ動画を、ComfyUIの画面で選択中の **Load Video** ノードに送れます（画像版の Send to LI node の動画版です）。

### ファイルを変換する
音声または動画を含めて複数選択すると、一括操作バーに **変換...** が現れます。

1. 変換したいファイルを選び、**変換...** を押します。
2. 出力形式（FLAC／MP3／Opus／M4A／WAV）と、必要ならビットレート・サンプルレート・チャンネル数を決めます。
3. 実行すると、同じフォルダに別のファイルとして保存されます（同名があるときは `名前_converted` のように連番が付き、上書きはされません）。

動画を選んだときは、音声トラックだけを取り出して保存します。

| 引き継ぎ | 説明 |
| --- | --- |
| ワークフロー情報 | MP3・FLAC・Opus・M4A には引き継がれる。WAVには引き継げない（通知が出る） |
| お気に入り・タグ・メモ・グループ | 引き継ぐかを選べる |
| 元ファイルの削除 | 変換に成功したあとで削除するかを選べる（確認画面あり） |

> **ポイント**
> OGG は再生はできますが、変換の出力形式には選べません。
> ほかの動画編集ソフトを入れなくても、Workflow Studioだけで変換できます。

> **ポイント：Videoタブでの活用**
> Video の Asset サブタブでは、音声ファイルを「BGMに設定」したり、「サウンドとして追加」したりできます（第11章 11-4）。

> **この章のまとめ**
> - ギャラリーのOutputで、生成した画像をフォルダごとに見返せる。プロンプトの言葉でも検索できる
> - 詳細パネルのプロンプトタブで、画像の生成に使ったプロンプトがすぐ分かる
> - 「GenUI」で生成UIに、「コピー＆キャンバスへ送る」でノード画面に、同じワークフローを再現できる
> - 再現するときは、シードのモードを Workflow（または Fixed）にする
> - メタデータサブタブに画像をドロップすると、モデル・LoRA・プロンプトを詳しく調べられる
> - Sボタンで、文章の意味や「似た画像」から探せる（セマンティック検索）
> - 音声ファイルも一覧・再生・変換できる

# 第9章 WS Library － ComfyUI画面の中で使う

ここまでの章では、Workflow Studio本体（タブが並ぶ画面）を中心に使ってきました。
この章では、ComfyUIのノード画面の横に開く **WS Library（Workflow Studio Library）** を使います。

WS Libraryを使うと、Workflow Studioで整理したワークフロー・ノード・モデル・プロンプトを、
**ノード画面にドラッグ＆ドロップするだけ** で使えます。
ノード画面で作業する時間が長い方ほど、便利さを実感できる機能です。

---

## 9-1 WS Libraryを開く

1. ComfyUIのノード画面を開きます。
2. 上部メニューに追加された **WS Library** ボタン（四角が並んだアイコン）を押します。

画面の端にパネルが開きます。もう一度ボタンを押すと閉じます。

### 6つのタブ
パネルの上部には、1文字のタブが並んでいます。マウスを重ねると、正式な名前が表示されます。

| タブ | 名前 | できること | 本書 |
| --- | --- | --- | --- |
| W | Workflows | ワークフローを読み込む | 9-2 |
| N | Nodes | ノードやノードセットを置く | 9-2 |
| M | Models | モデルを読み込むノードを置く | 9-2 |
| P | Prompts | 保存したプロンプトを置く・コピーする | 9-2 |
| I | Information | 画像やワークフローの中身を調べて、使われた素材を置く | 9-3 |
| A | AI TOOL | 翻訳やチャットなどのAI機能を使う | 第10章 |

各タブの中には、さらに小さなタブ（サブタブ）があります。
多くのタブで、次のサブタブが共通して使えます。

- **All** － すべて
- **★ Favorites** － Workflow Studio本体でお気に入りに登録したもの
- **Groups** － Workflow Studio本体で作ったグループごと

また、各サブタブの検索欄で、名前を入力して絞り込めます。

> **ポイント**
> WS Libraryに表示される内容は、Workflow Studio本体での整理（お気に入り・グループ・バッジ）と連動しています。
> 本体でしっかり整理しておくほど、WS Libraryも使いやすくなります。

---

## 9-2 ドラッグ＆ドロップでキャンバスに置く

WS Libraryの基本操作は、とてもシンプルです。

| 操作 | 動き |
| --- | --- |
| キャンバスへドラッグ＆ドロップ | ドロップした位置に置く・読み込む |
| ダブルクリック | 画面の中央付近に置く・読み込む |

### W － ワークフローを読み込む
ワークフローをキャンバスへドラッグ（またはダブルクリック）すると、そのワークフローが読み込まれます。
エクスプローラーからワークフローのファイルをドロップしたときと同じ動きです。

サブタブ：All／★ Favorites／Groups／By Badge（バッジごと）

> **ポイント**
> Workflow Studio本体をブックマークから開いていて「キャンバスへ送る」が使えない場合は、
> このWタブに対象のワークフローが表示されるので、ここからドラッグしてください（第4章 4-6）。

### M － モデルを置く
モデルをキャンバスへドラッグすると、**そのモデルが選ばれた状態の読み込みノード** が置かれます。

| モデルの種類 | 置かれるノード |
| --- | --- |
| Checkpoint | Load Checkpoint（CheckpointLoaderSimple） |
| LoRA | Load LoRA（LoraLoader） |
| VAE | Load VAE（VAELoader） |
| ControlNet | Load ControlNet Model（ControlNetLoader） |
| UNET | Load Diffusion Model（UNETLoader） |
| TextEncoder | Load CLIP（CLIPLoader） |
| Hypernetwork | HypernetworkLoader |

ノードを一覧から探して、置いて、ファイル名をプルダウンから選んで……という手間がなくなります。
置いたあとは、ほかのノードと線でつないで使います。

サブタブ：All／★ Favorites／Groups／By Type（種類ごと）

> **ポイント**
> Embeddingには読み込み用のノードがないため、キャンバスに置くことはできません。

> **ポイント：LoRAをまとめて置く**
> LoRAのグループには **All N LoRAs**（Nはグループ内のLoRAの数）という項目が表示されます。
> これをドラッグすると、グループ内のLoRAがすべて入った状態の `Lora Loader (LoraManager)` ノードが置かれます。
> （カスタムノード **ComfyUI-Lora-Manager** が必要です）

### P － プロンプトを置く
保存したプリセット（第7章）をキャンバスへドラッグすると、
ポジティブ・ネガティブのプロンプトが入った **Prompt Text (WFS)** ノードが置かれます。
これはWorkflow Studioに付属しているノードで、プロンプトの文章を出力します。

プロンプトを貼り付けたいだけのときは、項目の **P**（ポジティブ）／**N**（ネガティブ）ボタンでコピーできます。

サブタブ：All／★ Favorites／Categories（カテゴリーごと）／Groups

### N － ノードを置く
ノードをキャンバスへドラッグすると、そのノードが置かれます。
よく使うノードをWorkflow Studio本体の **ノード** タブでお気に入りに登録しておくと、すぐに取り出せます。
Nタブの一覧で、ノードを **Alt＋クリック** すると、その場でお気に入りのオン／オフを切り替えられます（v0.8.0〜）。
Nタブは、ノードの詳細情報を待たずに一覧を先に表示するため、以前より速く開きます。

サブタブ：All／★ Favorites／Groups／Sets／Category（カテゴリーごと）／Package（カスタムノードのパッケージごと）

### ノードセット － よく使う組み合わせを丸ごと保存する
**ノードセット** は、複数のノードとそのつながりを、ひとまとまりで保存したものです。
「いつも同じ組み合わせで使うノード群」を保存しておけば、ドラッグ1回で丸ごと置けます。

**ノードセットを作る**
1. ComfyUIのノード画面で、保存したいノードを選択します（Ctrlキーを押しながらクリック、またはドラッグで範囲選択）。
2. 選んだノードの上で **右クリック** し、**Save as Node Set** を選びます。
3. 名前を付けて保存します。

**ノードセットを使う**
WS Libraryの **N** タブの **Sets** サブタブから、キャンバスへドラッグします。

> **例**
> 「顔を自動で補正するノード群」や「高解像度化（アップスケール）のノード群」など、
> どのワークフローにも後から付け足したい部品をセットにしておくと便利です。

---

## 9-3 Informationタブで画像の中身を調べる

**I（Information）** タブは、画像やワークフローのファイルを調べて、
**使われていたモデルやプロンプトを、そのままキャンバスに置ける** 機能です。
ギャラリーのメタデータ（第8章 8-2）を、ノード画面の中で使えるようにしたものと考えてください。

### 使い方
1. WS Libraryの **I** タブを開きます。
2. 調べたいファイル（ComfyUIで作ったPNG・WebP・MP4・WebMの画像や動画、またはワークフローのJSON）を、パネルにドロップします。
3. ファイルの中から見つかった素材が、サブタブに分かれて表示されます。

| サブタブ | 内容 | キャンバスへドラッグすると |
| --- | --- | --- |
| model | Checkpoint・VAE・Diffusion Model・Text Encoder | 対応する読み込みノードが置かれる |
| lora | 使われていたLoRAと、その強さ | LoRAの読み込みノードが置かれる |
| Prompts | ポジティブ（POS）・ネガティブ（NEG）のプロンプト | プロンプトの入ったテキストエンコードノードが置かれる |

プロンプトの項目をクリックすると全文が表示され、**Copy** でコピーもできます。

### こんなときに便利
- 「前に作ったあの画像と、同じモデルとLoRAで新しいワークフローを組みたい」
- 「ネットで見つけたワークフローのプロンプトだけ借りたい」
- 「この画像、どのLoRAをどれくらいの強さで使っていたっけ？」

ワークフローを丸ごと読み込むのではなく、**必要な部品だけを取り出して使える** のがポイントです。

---

## 9-4 WS Libraryの見た目を変える

WS Libraryのパネル内にある **歯車ボタン**から、パネルの配色を設定できます。

- パネルの背景色
- サブヘッダーの背景色
- 文字の色・補助的な文字の色
- 枠線の色

ComfyUIのテーマに合わせて調整すると、違和感なく使えます。
設定はブラウザに保存され、次に開いたときも反映されます。

> **この章のまとめ**
> - WS Libraryは、ComfyUIのノード画面の横に開く「素材の棚」
> - W・N・M・P のタブから、ワークフロー・ノード・モデル・プロンプトをドラッグ（またはダブルクリック）で置ける
> - Mタブからモデルをドラッグすると、モデルが選ばれた状態の読み込みノードが置かれる
> - 右クリックの「Save as Node Set」で、よく使うノードの組み合わせを保存できる
> - Iタブに画像をドロップすると、使われていたモデル・LoRA・プロンプトを取り出して使える

# 第10章 AI TOOL － ローカルAIを助手にする

Workflow Studioは、パソコンの中で動く **ローカルAI（大規模言語モデル）** と連携できます。
ローカルAIを用意すると、次のようなことができるようになります。

- 日本語で考えた内容を、英語のプロンプトに翻訳する
- AIとチャットしながら、プロンプトのアイデアを出してもらう
- 画像を見せて、その画像の説明やプロンプト、タグを作ってもらう
- ワイルドカード用の候補リストを作ってもらう

インターネット上のサービスではなく、自分のパソコンの中で動くので、
**入力した内容や画像が外部に送られない** のが大きな特長です。

> **ポイント**
> AI機能は「あると便利」な機能です。使わなくても、Workflow Studioの基本機能はすべて使えます。
> パソコンの性能（特にGPUのメモリ）に余裕がある方は、ぜひ試してみてください。

---

## 10-1 ローカルAIソフトを準備する

### 対応しているソフト
Workflow Studioは、次の4つのローカルAIソフトに対応しています。

| ソフト | 特徴 | 標準のアドレス |
| --- | --- | --- |
| **Ollama**（オラマ） | 定番。モデルのダウンロードから実行までかんたん | `http://localhost:11434` |
| **LM Studio** | 画面で操作できる。モデル探しもアプリ内でできる | `http://localhost:1234` |
| Lemonade Server | AMD製のGPU・NPUでも動かしやすい | `http://localhost:13305` |
| Unsloth | APIキーなどの追加設定が必要（上級者向け） | `http://localhost:8888` |

はじめての方には **Ollama** をおすすめします。本章では、Ollamaを例に説明します。

> **ポイント**
> アドレスの `localhost` は「自分のパソコン」、その後ろの数字は **ポート番号** です（第2章 2-4）。
> ComfyUIと同じように、AIソフトもそれぞれ決まったポート番号で待ち受けています。

### Ollamaの準備
1. Ollamaの公式サイトから、お使いのOS用のインストーラーをダウンロードして、インストールします。
2. Ollamaを起動します（Windowsでは、インストール後に自動で起動し、タスクバーの通知領域に常駐します）。
3. 使うAIモデルをダウンロードします。コマンドプロンプトなどで、次のように入力します。

   ```
   ollama pull （モデル名）
   ```

   モデル名は、Ollamaの公式サイトのモデル一覧で確認できます。

> **モデル選びの目安**
> - **画像を読み取る機能（VLM）も使いたい** → 画像入力（vision）に対応したモデルを選ぶ
>   （作者の検証では、Gemma 4 の `e4b` などで画像生成・画像読み取りがうまく動いています）
> - **GPUのメモリが少ない** → パラメータ数の小さいモデル（数B＝数十億程度）を選ぶ
> - 翻訳の精度を重視するなら、日本語が得意なモデルを選ぶ
>
> AIモデルの世界は変化が速いので、新しいモデルも試してみてください。

> **注意：GPUのメモリの取り合い**
> ローカルAIも、画像生成と同じく **GPUのメモリ（VRAM）** を使います。
> 両方を同時に動かすと、メモリが足りなくなって画像生成が遅くなったり、エラーになったりします。
> 対策は 10-3 で説明します。

---

## 10-2 AI TOOLタブを使う

Workflow Studio本体の **AI TOOL** タブを開きます。
画面は4つの部分に分かれていて、すべて同時に表示されます。

| 部分 | できること |
| --- | --- |
| 翻訳 | 日本語・英語・中国語などの翻訳 |
| Chat | AIとの会話。条件がそろえば、会話から画像生成も |
| TOOLS | 画像の読み取り（VLM）、ワイルドカード作成 |
| 設定 | 使うAIソフト・モデルの設定 |

### 最初に：設定でAIソフトとつなぐ
1. **設定** の **バックエンド** で、使うソフト（例：Ollama）を選びます。
2. **接続設定** のアドレスを確認します。Ollamaを標準のまま使っている場合は、変更不要です。
3. **接続テスト** を押します。「接続成功」と表示されればOKです。
4. **モデル選択** の **更新** を押し、一覧から使うモデルを選びます。
5. **設定を保存** を押します。

> **ポイント**
> ここでの設定は、ComfyUI側のWS Libraryの **A（AI TOOL）** タブと共通です。
> 一方、プロンプトタブ（第7章）とTaggerタブには、それぞれ専用の **歯車ボタン** 設定があります。
> 「AI TOOLタブでは使えるのに、プロンプトタブでは Disconnected」というときは、プロンプトタブの歯車ボタンでも同じように設定してください。

> **うまくつながらないとき**
> - Ollamaなどのソフトが起動しているか確認します。
> - LM Studioは、アプリ内で **サーバーを起動** しておく必要があります。
> - アドレスのポート番号が、ソフト側の設定と合っているか確認します。
> - モデルの一覧が空のときは、モデルがダウンロードされているか確認します。

### 翻訳
1. 翻訳元と翻訳先の言語を選びます（**⇄（入れ替え）** ボタンで入れ替え）。
2. 入力欄に文章を書き、**翻訳** を押します。
3. 結果を **コピー** して、生成UIやプリセットに貼り付けます。

> **ポイント**
> 小さなモデルは、翻訳せずに元の文章をそのまま返してしまうことがあります。
> その場合は「モデルが原文をそのまま返しました」と表示されるので、別のモデルを試してください。

### Chat
入力欄に話しかけて、**Enter** で送信します（**Shift＋Enter** で改行）。
会話の流れを覚えているので、「もっと明るい雰囲気にして」のような続けての依頼もできます。
**Clear** で会話をリセットします。

> **ポイント：チャットから画像を生成する（上級）**
> 「ツール呼び出し（Tool Calling）」に対応したモデルを使うと、
> チャットで「猫の絵を描いて」と頼むだけで、生成UIに読み込んだワークフローで画像が生成され、チャット内に表示されます。
> この機能は、入力欄の横の **画像生成を許可する** のチェックでオン・オフできます。

### TOOLS － 画像を読み取る（VLM）
画像入力に対応したモデル（VLM）を使うと、画像の内容をAIに読み取らせることができます。

1. **TOOLS** の枠に、画像（PNG／JPG／WebP）をドロップします。
2. 作業を選びます。

   | 作業 | 内容 |
   | --- | --- |
   | 画像の解説 | 画像に何が写っているかを文章で説明する |
   | プロンプト作成 | 画像を再現するためのプロンプトを作る |
   | Create tags（英語表示のまま） | 画像の要素をタグ形式で書き出す |
   | Create wildcards（英語表示のまま） | カテゴリー名と件数を指定して、ワイルドカードの候補を作る（画像は不要） |

3. **実行** を押します。結果はコピーして使えます。

> **例**
> 気に入ったイラストの雰囲気をまねしたいとき、その画像から「プロンプト作成」をして、
> できたプロンプトを生成UIで使ってみる － という使い方ができます。

### ComfyUIの画面の中でも使える
同じAI機能は、ComfyUI側のWS Libraryの **A** タブでも使えます。
ノード画面で作業しながら、ちょっと翻訳したいときに便利です。

## 10-3 VRAMの解放とメモリ管理

10-1で触れたとおり、ローカルAIと画像生成は、GPUのメモリ（VRAM）を取り合います。
Ollamaは、一度使ったモデルをしばらくメモリに置いたままにするため、
AIを使ったあとに画像生成をすると、メモリが足りなくなることがあります。

### 手動で解放する
AI TOOLの設定にある **モデルをアンロード** を押すと、AIモデルがメモリから降ろされ、VRAMが空きます。
（Ollamaの場合は、読み込まれているすべてのモデルが降ろされます）

### 生成の前に自動で解放する
設定タブの **VRAM調整（Ollama）** で、画像生成の直前に自動でOllamaのモデルを降ろすように設定できます。

| 生成前の動作 | 動き |
| --- | --- |
| 何もしない | 自動では降ろさない |
| 空きが目標未満のときだけ必要な分をアンロード | 空きVRAMが **目標の空き（GB）** より少ないときだけ降ろす |
| 毎回すべてアンロード | 生成のたびに、必ずすべて降ろす |

> **ポイント**
> どれを選べばよいか迷ったら、「空きが目標未満のときだけ必要な分をアンロード」がおすすめです。
> 目標の空きには、画像生成に必要なメモリの量（使うモデルによって異なります）を目安に入力します。
> **今すぐすべてアンロード** ボタンで、その場ですぐに解放することもできます。

> **注意**
> この自動解放は、Ollamaだけが対象です。LM Studioなどを使っている場合は、手動で解放してください。

## 10-4 セキュリティ上の注意

### 標準では「自分のパソコン」のAIにだけつながる
安全のため、Workflow StudioがつなぐAIソフト（Ollama、LM Studioなど）は、標準では
**同じパソコンの中（localhost／127.0.0.1）で動いているもの** に限られています。

### 別のパソコンのAIを使いたいとき
家庭内LANにある別のパソコン（GPUの強いパソコンなど）でOllamaを動かして使いたい場合は、
環境変数 **`WFS_ALLOWED_BACKEND_HOSTS`** に、つなぎたいパソコンのアドレスを登録して、ComfyUIを再起動します。

```
WFS_ALLOWED_BACKEND_HOSTS=192.168.1.20:11434
```

複数ある場合は、カンマ（,）で区切って並べます。
環境変数の設定方法は、ComfyUIの起動方法によって異なります。

### ComfyUIを `--listen` 付きで起動している場合
ComfyUIを `--listen` オプション付きで起動すると、同じネットワークにいるほかのパソコンやスマホからも
ComfyUI（とWorkflow Studio）にアクセスできるようになります。
その場合、アクセスできる人なら誰でも、あなたのAIソフトや画像を使えてしまいます。

> **注意**
> `--listen` は、家庭内LANなど **信頼できるネットワークでだけ** 使ってください。
> カフェや公共のWi-Fiでは使わないようにしましょう。

> **この章のまとめ**
> - ローカルAI（Ollamaなど）を用意すると、翻訳・チャット・画像の読み取りができる。入力内容は外部に送られない
> - AI TOOLタブの設定で、バックエンド・アドレス・モデルを選び、接続テストをする
> - プロンプトタブとTaggerタブには、別に歯車ボタンの設定がある
> - AIと画像生成はVRAMを取り合う。「モデルをアンロード」や「VRAM調整（Ollama）」で解放する
> - 標準では自分のパソコンのAIにだけつながる。`--listen` は信頼できるネットワークだけで

## 11-1 ノードタブ － インストール済みのノードを一覧する

## 11-2 Tagger － 画像からタグを自動で作る

**Tagger** タブは、画像を読み取って、その画像を表すタグ（`1girl, long hair, smile` など）を自動で作る機能です。
アニメ系のモデルのプロンプト作りや、学習用画像のタグ付けに使えます。

### 3つのサブタブ
| サブタブ | できること |
| --- | --- |
| Single | 1枚の画像からタグを作る |
| Batch | フォルダ内の画像に、まとめてタグを付ける（画像と同じ名前の `.txt` ファイルを書き出すことも可能） |
| DB | タグを付けた画像の記録を検索・編集する |

### 使い方（Single）
1. 画像を、プレビュー部分にドロップします（ギャラリーの詳細パネルの **Tagger** ボタンからも開けます）。
2. 使うモデルを選び、実行ボタンを押してタグを作ります。
3. 結果を使います。

   | ボタン | 動き |
   | --- | --- |
   | GenUI:P | 生成UIのポジティブプロンプトに追加する |
   | Send to Prompt | プロンプトタブのポジティブプロンプトに追加する |

**しきい値** のスライダーで、どのくらい確かなタグまで出すかを調整できます。
数値を上げるとタグは少なく確かなものだけに、下げると多くなります。

### 準備が必要
Taggerを使うには、次の準備が必要です。

1. **タグ付け用のモデル**（WD Tagger など）を、ComfyUIの `models/tagger/（モデル名）/` フォルダに置きます。
   フォルダには、`.onnx` ファイルと `selected_tags.csv` を入れます。
2. **追加のPythonパッケージ** をインストールします。
   Workflow Studioのフォルダにある `requirements.txt` を使います。

   ```
   （ComfyUIのPython） -m pip install -r requirements.txt
   ```

   「ComfyUIのPython」の場所は環境によって違います。第2章 2-6 の表で確認してください
   （例：Windowsのポータブル版では `python_embeded` フォルダの中の `python.exe`）。

> **注意**
> パソコンにもともと入っているPythonにインストールしても、ComfyUIからは使えません。
> 必ず、**ComfyUIが使っているPython** にインストールしてください。
> 分からない場合は、ComfyUI Managerの機能でパッケージをインストールする方法もあります。

> **ポイント**
> ローカルAI（第10章）の画像読み取り（VLM）と組み合わせて、両方の結果をまとめたタグを作ることもできます。

## 11-3 Image Edit － 生成した画像にちょっと手を加える

**Image Edit** タブは、レイヤー機能を持った簡易画像編集ツールです。
生成した画像に文字を入れたり、一部を描き直すためのマスクを作ったりできます。

### 主な機能
| ツール | できること |
| --- | --- |
| Select | レイヤーの移動・拡大縮小・回転 |
| Draw | ペンで描く（ペンタブレットの筆圧にも対応） |
| Text | 文字を入れる |
| Shape | 四角・丸・線を描く |
| Fill | 塗りつぶし・グラデーション |
| Mask | 描き直したい部分を指定する（マスク作成） |
| Blur | ぼかし・モザイク |
| BG Remove | 背景を消す |
| Inpaint | マスクした部分を、生成UIのワークフローで描き直す |

- 画像は、ドラッグ＆ドロップ、**File Open**、またはギャラリーの **Image Edit** ボタンで開きます。
- 編集した画像は、**Save PNG**（ダウンロード）、**Save to Gallery**（ギャラリーに保存）などで保存します。
- **Ctrl＋Z** で元に戻す、**Ctrl＋Y** でやり直しができます。

### インペイント（部分の描き直し）
Image Editのいちばん便利な使い方が、**インペイント** です。
「顔だけ描き直したい」「手が崩れたところだけ直したい」というときに使います。

1. 生成UIに、インペイント用のワークフロー（付属サンプルの `ws_inpaint_basic` など）を読み込みます。
2. Image Editで画像を開き、**Mask** で描き直したい部分を塗ります。
3. **Inpaint** ツールで実行すると、塗った部分だけが描き直されます。

> **ポイント**
> 背景を消す機能の高品質版や、より高度なマスク機能を使うには、
> 作者の別のカスタムノード **comfyui-mask-editor-one** が必要です。
> PSD形式での保存・読み込みには、追加のPythonパッケージ（psd-tools）が必要です。

## 11-4 Video － 動画を作る・つなぐ

**Video** タブは、動画生成モデルを使って、画像や文章から短い動画を作るための専用画面です。

### 対応している動画生成モデル
- **MiniMax H3**（画像から動画）
- **LTX-2.5**（文章から動画、画像から動画、最初と最後の画像を指定して動画）
- **Wan2.2**（文章から動画）

対応するワークフローを、ワークフロータブの **Videoに読み込み** で読み込んで使います（第4章 4-6）。

### 主な機能
| サブタブ | できること |
| --- | --- |
| Plan | 動画を「ブロック」に分け、ブロックごとにプロンプト・長さ・最初／最後の画像を決めて、順番に生成する |
| Edit | 生成した動画や画像を並べて、切り取り・つなぎ合わせ・文字入れ・BGM付けをして書き出す |
| Asset | 生成した動画や画像、音声を一覧する。音声は「BGMに設定」や「サウンドとして追加」ができる（種類フィルタの Audio Only で音声だけ表示） |

そのほか、動画の好きな場面を静止画として保存する **Frame** や、動画をGIFアニメに変換する **GIF** の機能もあります。

### アセット登録と音声変換（v0.8.9〜）
- **アセット登録** － 左側の動画ソースパネルのボタンです。パソコン内の動画を、outputフォルダ（`output/video`）へコピーして「Video Assets」グループに登録します。
  登録すると、Assetサブタブの一覧に出て、Editなどで使えるようになります。
  すでにoutputフォルダにある動画（Assetで選んだものや生成結果）は、コピーせずにグループへの登録だけを行います。同じ名前があるときは、名前の後ろに連番が付きます。
- **音声変換...** － Editサブタブの、クロップのボタンの横にあるボタンです。選んだ動画クリップの音声だけを、FLAC・MP3・Opus・M4A・WAVに変換して `output/video` に保存します。
  ギャラリーの変換と同じ画面です。音声が入っている動画クリップだけが対象です。
- 音声変換のボタンを押すと、次の画面が開きます。**出力形式**（FLACなど）、**サンプルレート**、**チャンネル** を選び、**変換** を押します。
  「埋め込みのprompt/workflowタグを引き継ぐ」にチェックを入れると、タグを持つ形式（FLACなど）で、元の動画の情報を引き継げます。

- 動画ソースパネルは少し広くなり、ファイル名が1行で表示され、ボタンも横一列に並ぶようになりました。

> **注意**
> 動画生成は、画像生成よりもはるかに多くのGPUメモリと時間を使います。
> 使うモデルの必要スペックを確認してから試しましょう。

**設定** タブでは、Workflow Studio全体の設定をします。
項目ごとに折りたたまれているので、見出しをクリックして開きます。

ワークフロータブの詳細画面の **デフォルトに設定** ボタンからも設定できます。

### デフォルトCheckpoint
ネットから入手したワークフローには、手元にないモデルが指定されていることがよくあります（第5章 5-3）。
**デフォルトCheckpoint** を設定してオンにしておくと、生成UIにワークフローを読み込むたびに、
Checkpointが自動で指定のモデルに差し替わります。モデルの選び直しの手間が省けます。

**データ管理** では、Workflow Studioで整理した情報（お気に入り・バッジ・グループ・プリセットなど）を
ファイルに書き出したり（エクスポート）、読み込んで元に戻したり（インポート）できます。

**フルバックアップ (ZIP)** を使うと、スタイルやLabのプランなどのフォルダ単位のデータも含めて、まとめてバックアップできます。

> **ポイント**
> パソコンの買い替えやComfyUIの入れ直しの前には、必ずバックアップを取っておきましょう。
> 時間をかけて整理した情報を、そのまま新しい環境に引き継げます。
> （安全のため、APIキーはバックアップに含まれません）

## 11-6 連携ソフト：ComfyUI Comic Creator － 生成した画像でマンガを作る

**ComfyUI Comic Creator**（以下、Comic Creator）は、Workflow Studioと同じ作者が開発している、
ComfyUI上で動く **マンガ制作用** のカスタムノードです。
Workflow Studioとは別にインストールするソフトですが、両方を入れると連携して使えます。

### Comic Creatorでできること
| 機能 | 内容 |
| --- | --- |
| コマ割り | テンプレートを選んで、ページにコマを作る（自作テンプレートも登録可能） |
| 画像の配置 | コマに画像をドラッグ＆ドロップで配置する |
| フキダシ・テキスト | 縦書き・横書きのセリフ、さまざまな形のフキダシ、効果文字を入れる |
| マンガ効果 | 集中線・スクリーントーン・網点（ハーフトーン）などを加える |
| 画像の編集 | レイヤー付きの画像編集（Image タブ） |
| AIでの自動作成 | お題から、ストーリー・脚本・コマ割りをAIで下書きする（Auto タブ） |
| 書き出し | JPEG／PNG／WebP／SVG／PDF／**EPUB** 形式で出力する |

### Workflow Studioとの連携
両方をインストールすると、次のような連携ができます。

- **Comic Creatorの中でWorkflow Studioのギャラリーを使う**
  Comic Creatorの中にWorkflow Studioのギャラリーが表示され、生成した画像を選んで **Send CC** ボタンでコマに送れます。
  （Send CCボタンは、Comic Creatorの中で開いたギャラリーにだけ表示されます）
- **Comic Creatorから画像を生成する**
  Comic Creatorの画面から、Workflow Studio（生成UI）を通して、コマに入れる画像を生成したり（T2I）、
  描いたラフや配置した画像をもとに描き直したり（I2I・インペイント）できます。

「Workflow Studioで画像を作る → Comic Creatorでマンガにまとめる」という流れで、
画像生成からマンガの完成までを、ComfyUIの中だけで行えます。

### インストールと起動
1. ComfyUI Managerの **Install via Git URL** に、次のURLを入力してインストールします。

   ```
   https://github.com/ketle-man/comfyui-comic-creator
   ```

   （手動の場合は、Workflow Studioと同じく `ComfyUI/custom_nodes/` に `git clone` します）

2. ComfyUIを再起動します。
3. ComfyUIの上部メニューに追加された **CC** ボタンを押すと、Comic Creatorが新しいタブで開きます。

> **ポイント**
> Comic Creatorの詳しい使い方は、アプリ内の **ヘルプ** タブ（日本語対応・検索機能あり）を参照してください。

# 第12章 困ったときは（トラブルシューティング／FAQ）

この章では、Workflow Studioを使っていてよく起こるトラブルと、その対処方法をまとめます。

## 12-1 起動・接続のトラブル

### Wボタンが表示されない
| 原因 | 対処 |
| --- | --- |
| インストール後にComfyUIを再起動していない | ComfyUIを完全に終了して、起動し直す（ブラウザの再読み込みだけでは反映されません） |
| フォルダの場所が違う | `ComfyUI/custom_nodes/ComfyUI-Workflow-Studio` にフォルダがあるか確認する。フォルダが二重になっていないかも確認 |
| ComfyUIが古い | ComfyUI本体を更新する |

### Workflow Studioのページが開かない
- ComfyUIは起動していますか？ Workflow StudioはComfyUIの中で動いているため、ComfyUIを終了すると開けません。
- アドレスの **ポート番号** は合っていますか？ ComfyUIを開いているブラウザのアドレス欄で確認できます（第2章 2-4）。

### 生成UIが「Disconnected」になる
1. ComfyUIが起動していて、ComfyUIの画面で画像を生成できるか確認します。
2. 生成UIの上部の **Connect** を押します。
3. それでもつながらない場合は、ブラウザのページを再読み込みします。

### 更新したのに動きが変わらない
Workflow Studioを更新（アップデート）したあとは、必ずComfyUIを再起動してください。
それでも古い動きのままのときは、ブラウザのキャッシュが残っている可能性があります。
**Ctrl＋F5**（強制再読み込み）を試してください。

## 12-2 ワークフローのトラブル

### ワークフローが一覧に出てこない
| 原因 | 対処 |
| --- | --- |
| 一覧が古いまま | ワークフロータブの **更新** を押す |
| 絞り込みがかかっている | ツールバー右端の **× クリア** を押す |
| 別のフォルダに保存している | 設定タブの「ワークフローデータフォルダ」を確認する |

### ノードが赤く表示される（missing）
ワークフローを読み込んだとき、ノードが赤く表示されたり、「見つからないノードがあります」と表示されたりすることがあります。
これは、そのワークフローに必要な **カスタムノードがインストールされていない** という意味です。

**対処**
1. ComfyUIの **Manager** を開きます。
2. **Install Missing Custom Nodes**（不足しているカスタムノードをインストール）を選びます。
3. 表示されたカスタムノードをインストールし、ComfyUIを再起動します。

> **ポイント**
> ワークフロータブの **GenerateUIチェック**（第4章 4-7）で「変換 ×」になるのも、多くはこれが原因です。
> バッジにマウスを重ねると、足りないノードの名前が表示されます。

### 生成UIで「使えない」と判定された
| 判定 | 意味と対処 |
| --- | --- |
| 変換 × | 必要なカスタムノードがない → 上の「ノードが赤く表示される」を参照 |
| 変換 △ | 手元にないモデルなどが指定されている → 生成UIで選び直す（12-3） |
| 操作性 △／× | 生成UIに表示されない設定が多い → 生成はできることが多い。細かい設定はComfyUIのノード画面で変更する |

## 12-3 生成のトラブル

### 設定を変えたのに、結果が変わらない
いちばん多い原因は、**Apply の押し忘れ** です。
生成UIでは、モデルやSettings（ステップ数・サイズなど）の値を変えたあと、**Apply** を押さないとワークフローに反映されません（第5章 5-3）。
右側の **Raw JSON** を見ると、実際に反映されている値を確認できます。

### 読み込んだワークフローとは違う内容で生成される
**Batch** サブタブで、バッチの種類のチェックがオンのまま残っていると、
Generateを押したときにバッチ生成が実行されます（第5章 5-5）。
Batchサブタブを開き、Batch Queueの列のチェックをすべてオフにしてください。

### 思っていたのと違うモデルで生成される
ワークフローに保存されているモデルが手元にないと、別のモデルに自動で差し替えられることがあります。
その場合は「Checkpoint「…」が見つからず、無警告で別のモデルに差し替えられました」と表示されます。
（v0.8.7〜は、フォルダ名だけが違う同名のモデルが1つだけ手元にあれば、それに自動で差し替わります）
生成UIの **Model** サブタブで、使いたいモデルを選び直して **Apply** を押してください。

いつも同じモデルを使いたい場合は、設定タブの **デフォルトCheckpoint** を使うと便利です（第11章 11-5）。

### 同じ設定なのに、同じ画像にならない
生成パネルのシードのモードが **Random** になっていませんか？
同じ画像を作るには、シードを **Workflow**（ワークフローのシードをそのまま使う）か **Fixed**（Seed欄の値で固定）にする必要があります。
同じシード・同じ設定で続けて生成して新しい画像が増えないのは、ComfyUIが計算済みの結果を再利用しているためで、故障ではありません。
ギャラリーの画像を再現する手順は、第8章 8-3を参照してください。

### 生成が遅い・エラーで止まる（メモリ不足）
| 原因 | 対処 |
| --- | --- |
| ローカルAIがGPUメモリを使っている | AI TOOLの **モデルをアンロード** を押す。設定タブの **VRAM調整（Ollama）** を使う（第10章 10-3） |
| 画像サイズやBatch Sizeが大きすぎる | Settingsサブタブで Width・Height・Batch Size を小さくする |
| モデルがGPUに対して大きすぎる | より小さいモデル（GGUF版など）を使う |

### モデルを移動・削除したあとにエラーが出る
ComfyUIが、モデルの古い場所を覚えていることがあります。
ComfyUIのメニューの **Hard Reset**（キューのメニュー内）を実行するか、ComfyUIを再起動してください。

### 新しく入れたモデルが一覧に出てこない
生成UIの **Refresh Models**、またはモデルタブの **更新** を押してください。
それでも出てこない場合は、モデルを置いたフォルダが正しいか（第6章 6-1）を確認します。

## 12-4 AI機能のトラブル

### AI機能が「Disconnected」になる・つながらない
1. Ollamaなどのソフトが起動しているか確認します。
   LM StudioやLemonadeの場合は、アプリ内で **サーバーを起動** し、モデルを読み込んでおく必要があります。
2. 設定のアドレス（ポート番号）が、ソフト側と合っているか確認します。
3. **接続テスト** を押して、結果を確認します。

### AI TOOLタブでは使えるのに、プロンプトタブでは使えない
AIの設定は、場所によって別々に保存されています（第10章 10-2）。

| 場所 | 設定する場所 |
| --- | --- |
| AI TOOLタブ／WS LibraryのAタブ | AI TOOLタブの設定（共通） |
| プロンプトタブ | プロンプトタブのAI Assistantの **歯車ボタン** |
| Taggerタブ | Taggerタブの **歯車ボタン** |

### モデルの一覧が空になる
AIモデルがダウンロードされていない可能性があります。
Ollamaの場合は `ollama pull （モデル名）` でモデルをダウンロードしてから、モデル選択の **更新** を押してください。

### 別のパソコンのOllamaにつながらない
安全のため、標準では同じパソコンの中のAIソフトにしかつながりません。
環境変数 `WFS_ALLOWED_BACKEND_HOSTS` の設定が必要です（第10章 10-4）。

## 12-5 そのほかの機能のトラブル

### Taggerにモデルが表示されない
- `ComfyUI/models/tagger/（モデル名）/` フォルダに、`.onnx` ファイル（と `selected_tags.csv`）が入っているか確認します。
- 追加のPythonパッケージ（onnxruntime）が、**ComfyUIが使っているPython** にインストールされているか確認します（第11章 11-2）。

### PSD関連の機能がエラーになる
追加のPythonパッケージ（psd-tools）が必要です。
エラーメッセージに表示されるインストール用のコマンドを、ComfyUIが使っているPythonで実行してから、ComfyUIを再起動してください。

### セマンティック検索（Gallery）がうまく動かない
| 症状 | 原因 | 対処 |
| --- | --- | --- |
| GPUが検出されない（設定に「GPU未検出」と出る、実行がCPUになる） | ComfyUIのPythonに入っているonnxruntimeがCPU版 | ComfyUIを停止し、ComfyUIのPythonで `pip uninstall -y onnxruntime onnxruntime-gpu` のあと `pip install onnxruntime-gpu` を実行して、ComfyUIを再起動する（DirectMLは非対応） |
| Geminiで「GEMINI_API_KEYが未設定」と出る・キーが拒否される | `.env` にキーが無い、または行頭に `#` が付いている | プラグインの `.env`（`.env.example` をコピー）に `GEMINI_API_KEY=キー` と書き、ComfyUIを再起動する。`.env` は起動時にしか読み込まれない |
| 検索やSimilarの結果が出ない | 選んだフォルダにインデックス済みの画像が無い | 歯車ボタンでインデックスを作る。緑の点があるフォルダを選ぶ。モデルや精度を変えたときは「全件再作成」 |

### パートナーAPI（Nano Banana）が「認証に失敗しました」と出る
`.env` にComfy APIキーが無いのが原因です。プラグインの `.env` に `COMFY_API_KEY=キー`（platform.comfy.orgで発行）を書き、ComfyUIを再起動してください（第5章 5-8）。
`.env` は起動時にしか読み込まれません。

### ギャラリーに画像が出てこない
- ギャラリーの **Refresh** を押します。
- 設定タブの「ギャラリー Outputフォルダ」が、ComfyUIの画像保存先と合っているか確認します。

## 12-6 それでも解決しないときは

### Workflow Studioのヘルプを見る
Workflow Studioの **ヘルプ** タブにも、トラブルシューティングの情報があります。
本書の発行後に追加された情報が載っていることもあります。

### GitHubで質問・報告する
解決しない問題は、Workflow StudioのGitHubリポジトリの **Issues** で報告できます。
報告するときは、次の情報を添えると、原因が見つかりやすくなります。

- Workflow Studioのバージョン
- ComfyUIのバージョンと、インストール方法（ポータブル版、Desktop版、Stability Matrixなど）
- どの画面で、何をしたら、どうなったか
- ComfyUIを起動した黒い画面（コンソール）に表示されたエラーメッセージ
- ブラウザの開発者ツール（F12キー）の「Console」に表示された赤いエラーメッセージ

> **注意**
> エラーメッセージを貼り付けるときは、パソコンのユーザー名などの個人情報が含まれていないか確認しましょう。

> **この章のまとめ**
> - 困ったら「再読み込み」「更新ボタン」「ComfyUIの再起動」をまず試す
> - 赤いノードは、カスタムノードの不足。ComfyUI Managerの Install Missing Custom Nodes で解決
> - 設定が反映されないときは、Applyの押し忘れとBatchのチェックの残りを確認
> - メモリ不足は、ローカルAIのアンロードや画像サイズの見直しで対処
> - 解決しないときは、ヘルプタブやGitHubのIssuesを活用する

# おわりに

最後まで読んでいただき、ありがとうございました。

ComfyUIは、とても自由で奥の深いソフトです。
その自由さゆえに、はじめての方には「どこから手をつければいいのか分からない」ソフトでもあります。
Workflow Studioは、その入口を少しでも広げ、
「作ること」と「整理すること」をもっと気軽にしたいという思いから生まれました。

本書で紹介した使い方を、あらためて振り返ってみましょう。

1. **整理する** － ワークフロー・モデル・プロンプトを、サムネイルやバッジで見分けやすくする
2. **作る** － 生成UIで、ノード画面を触らずに画像を生成する
3. **貯める** － うまくいったプロンプトや設定を、プリセットやギャラリーに残す
4. **再現する** － 画像のメタデータから、同じ設定をすぐに呼び出す
5. **広げる** － バッチ生成やローカルAIで、試行錯誤のスピードを上げる

画像生成が上達するいちばんの近道は、**たくさん試して、うまくいったものを残していく** ことです。
